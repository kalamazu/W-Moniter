# 使用手册 · Chromium 监控容器

> 面向使用者和 agent。目标是「照着做就能用起来」。
> 想改代码看 `docs/设计文档.md`，想接 agent 看本文 §7–§8 与 `docs/AI-控制面.md`。

## 1. 这是什么

一个本机的页面观测 + 干预工具：用**真实的 Chrome** 打开目标站点，把它的请求、响应、
body、JS 源码、DOM、console、以及「页面实际收到了什么」全记下来，并且可以动手改包、注入脚本、
模拟真人点击输入。同时对外开一个只绑 `127.0.0.1` 的 HTTP API 和一个 MCP server，让 agent 能全面控制。

三个关键特征，决定了它和普通抓包工具的差别：

- **零污染**：承载目标页面的是独立进程的真 Chrome，不是 Electron；CDP 走 pipe，没有监听端口
- **先接管再放行**：启动时先停在 `about:blank`，等所有 target 都 attach 完才导航，首屏请求一条不漏
- **判据在页面侧**：改包有没有生效、点击有没有真点到，都由页面自己回报，不采信工具自述

## 2. 前置条件

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 系统 Node | **22+** | 存储进程用 `node:sqlite`；`MONITOR_NODE_PATH` 可指定 |
| Chrome | 已安装 | 不设则自动查找；`CHROME_PATH` 可指定 |
| 平台 | Windows / macOS / Linux | 本机开发环境是 Windows 11 + PowerShell 5.1 |
| 图形界面 | **有头环境** | 窗口必须真的显示出来，页面才有正确的 `outerWidth` / `visibilityState` |

> PowerShell 5.1 不支持 `&&`，多条命令用 `;` 连接。

## 3. 五分钟跑起来

```bash
# 1) 装依赖
npm install

# 2) 跑起来（开发模式，默认打开 https://example.com）
npm run dev

# 换个目标站点、换个 Profile、指定数据目录
$env:MONITOR_URL='https://example.com'; $env:MONITOR_PROFILE='L'; $env:MONITOR_DATA_DIR='F:\tmp\m1'; npm run dev
```

跑构建产物（验收脚本用的就是这条路）：

```bash
npm run build
npx electron .
```

> `electron.exe` 是 **GUI 子系统程序**，在 PowerShell 里直接 `.\node_modules\electron\dist\electron.exe .`
> 会**立刻返回**（PowerShell 不等 GUI 程序），看起来像「没反应」。要么用 `npx electron .`，
> 要么用 `Start-Process -FilePath .\node_modules\electron\dist\electron.exe -ArgumentList '.' -Wait`。

**数据目录**默认是 Electron 的 `userData` 路径，找起来不直观。建议一开始就显式指定
`MONITOR_DATA_DIR`——规则文件、数据库、profile、`control.json` 全在里面。

**怎么体面收工**：

- `MONITOR_AUTO_QUIT_MS=60000` —— 60 秒后自动退出（会把采集队列落盘）
- `MONITOR_QUIT_FILE=F:\tmp\stop` —— 该文件一出现就退出（比死等秒数精确）
- 直接关窗口也行。**别用 `taskkill` 硬杀**，队列里没落盘的东西会丢，还会留孤儿 chrome
- 收工要杀干净时，记得被监控的是真 Chrome：`taskkill /F /IM electron.exe /T` **和** `taskkill /F /IM chrome.exe /T`

九个 tab：

| Tab | 看什么 / 干什么 |
| --- | --- |
| **请求列表** | 全量请求，按类型 / 域名 / 状态过滤。10 万条以内虚拟滚动不掉帧 |

| **脚本** | 所有已加载 JS（含内联 / `eval` / Worker / SW），可搜索、可格式化。**仅 Profile L** |
| **统计** | 按类型 / 域 / 状态聚合，含大小与耗时 |
| **规则** | 规则编辑器，改完实时生效；命中统计也在这 |
| **控制台** | 执行 JS 表达式 + 页面 console 实时回流（500 条环形缓冲）。**仅 Profile L** |
| **环境** | 当前 Profile、能力矩阵、探针报告、指纹明细、拟人化输入入口 |
| **DOM** | DOM 树 + 命中样式 + 事件监听器，可高亮节点 |
| **会话** | 实例列表、Profile 切换、存储分区与各表行数 |

## 5. 常用任务

### 5.1 看某个页面发了哪些请求

开应用 → **请求列表** tab。要精确定位就用过滤：URL 子串、域名、状态（`2xx` / `404` 这种写法也行）、
类型（`XHR` / `Document` / `Script` / `Fetch`）。

### 5.2 看一条请求的全部证据

列表里点一行，右侧详情：

- **概览** —— 时序、大小、状态、body 摘要
- **头** —— 请求头 / 响应头
- **发起链** —— initiator 调用栈
- **body** —— 正文（大 body 默认只给摘要 + hash，正文在库里被 LRU 管着）

开了代理（`MONITOR_PROXY=1`）还会多出「三源关联 / 上游 IP / TLS 套件 / 网络分段」。

> 注意：**Worker / Service Worker 会话不发头**，落在这些会话里的请求看不到 req / resp headers。
> 这是内核行为，不是 bug。

### 5.3 改包 / 拦截 / mock

**规则** tab 写规则，或直接编辑规则文件（默认 `<数据目录>/rules.json`）。匹配维度有
URL / host / method / resourceType / frameUrl / status / 正则等；动作分两类：

- 网络类：block、redirect、改请求头、改响应头、改请求体、改响应体、delay、mock
- 注入类：按 `document_start` / `document_ready` 注入脚本

改完**实时生效**，不需要重启。命中情况在**规则** tab 的统计里看。

两条要记住的边界：

- **大 body 改写**只下沉「拿得到 `content-length`」的响应；chunked / 流式（含 SSE）不改
- 带 `resourceType` / `frameUrl` / `targetType` 约束的 body 规则**不下发到代理**（代理拿不到这些信号），
  日志会报条数

### 5.4 模拟真人点击 / 输入

**环境** tab 有输入入口，但更常用的是给 selector 让工具自己算坐标：

```bash
# 直接给选择器，不用自己算坐标（页面自己算，不受缩放/滚动影响）
POST /input  { "kind": "click", "selector": "#submit", "seed": 31 }
POST /input  { "kind": "type",  "selector": "#search", "text": "hello", "seed": 21 }
POST /input  { "kind": "move",  "x": 900, "y": 600, "seed": 20260919 }
POST /input  { "kind": "scroll","x": 640, "y": 400, "deltaY": 600 }
```

轨迹是贝塞尔弧线 + 变速 + 停顿 + 错字回退，**同 seed 可复现**。

> **`/input` 返回 ≠ 页面已经收到**：事件会在浏览器队列里排队，实测返回后还会继续投递 ~150ms。
> 要「点完立刻读结果」，留 ~200ms，或把读取并进同一次 `/evaluate`。

### 5.5 截图

```bash
POST /screenshot  { "fullPage": true }          # 整页（超 16000px 会截断并标 clamped）
POST /screenshot  { "nodeId": 42 }              # 只截某个节点
POST /screenshot  { "format": "jpeg", "quality": 80 }
```

落盘在 `<数据目录>/screenshots/`，结果里给绝对路径；MCP 那条路默认还会带上 image 块。

### 5.6 直接查库

```bash
node scripts/db-sql.mjs <数据目录>/monitor.db "select url,status,duration_ms from requests order by start_ts desc limit 5"
```

npm run test:smoke    # 全量冒烟：29 条 HTTP 路由 + 25 个 MCP 工具，一条都不落

## 7. HTTP API 手册

### 7.1 先发现地址和 token

控制服务绑 `127.0.0.1`，端口与 token 由应用写在数据目录的 `control.json`：

```json
{ "port": 52137, "token": "…", "pid": 12345, "startedAt": 1789820000000 }
```

```powershell
$info = Get-Content "$env:MONITOR_DATA_DIR\control.json" | ConvertFrom-Json
$base = "http://127.0.0.1:$($info.port)"
$h = @{ authorization = "Bearer $($info.token)" }
```

> **残留的 `control.json` 是个经典坑**：被硬杀的应用删不掉自己那份，agent 会连上一次的死数据。
> 判据是 `startedAt`，只认本次启动之后写的。

### 7.2 路由表（29 条）

**读**（`GET`，全部要 token）：

| 路由 | 说明 |
| --- | --- |
| `/status` | 连接状态、Profile、请求/脚本计数、存储健康 |
| `/capabilities` | 当前 Profile 的能力矩阵 |
| `/health` | 存活探针。**唯一免鉴权**的路由 |
| `/requests` | 请求列表。支持 `url`(别名 `urlPattern`) / `host`(`domain`) / `method` / `resourceType`(`type`) / `status` / `statusMin` / `statusMax` / `mimeType` / `initiatorType`(`initiator`) / `search`(`q`) / `since` / `until` / `minSize` / `maxSize` / `instance` / `limit` / `offset` / `order` |
| `/requests/:seq` | 单条请求完整详情（headers / 时序 / 三源 / 上游 / TLS / body 摘要） |
| `/requests/:seq/body` | 按 seq 取 body（`?withData=0` 只要摘要） |
| `/requests/:seq/body-live` | 库里没有时去浏览器缓冲区现捞一次 |
| `/stats` | 聚合统计 |
| `/timeline` | 瀑布图时间线 |
| `/scripts` | 脚本列表（不含源码）；`/scripts/stats` 统计；`/scripts/:hash` 取源码 |
| `/rules` · `/rules/stats` | 当前规则集 / 命中统计 |
| `/console` | 页面 console 回流（最多 500 条） |
| `/instances` · `/sessions` | 实例列表 / 会话管理视图 |
| `/dom/tree` · `/dom/inspect` | DOM 树（`?nodeId=&depth=`）/ 元素检查（`?selector=` 或 `?nodeId=`） |

**写**（`POST` + JSON body）：

| 路由 | body | 说明 |
| --- | --- | --- |
| `/navigate` | `{ url }` | 等 load 再回读落地 URL 与标题 |
| `/screenshot` | `{ format, quality, fullPage, nodeId, inline }` | 落盘 + 返回路径 |
| `/evaluate` | `{ expression }` | 页面侧求值。**Profile H 下明确拒绝** |
| `/probe` | `{ options }` | 跑检测探针，四组报告 + 是否建议切 Profile |
| `/input` | `{ kind, selector \| x,y, text, deltaY, seed }` | 拟人化输入，`kind` = `move`/`click`/`type`/`scroll` |
| `/dom/highlight` | `{ nodeId, on }` | 页面里高亮节点 |
| `/rules` | 完整 RuleSet | 覆盖式保存 |
| `/sessions/profile` | `{ profile: "L" \| "H" }` | 切 Profile（收工重启，约几十秒） |
| `/clear` · `/console/clear` | — | 清采集缓冲（计数同时归零，库里的历史不动）/ 清 console |

约定：**真结果就是响应体本身**，不套 `{ ok, data }`。

### 7.3 几条 curl 示例

```bash
# 存活（免鉴权）
curl http://127.0.0.1:52137/health

# 最近的 XHR，只要 5 条
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/requests?resourceType=XHR&limit=5"

# 404 和 5xx
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/requests?status=404"

# 点一个按钮（给选择器，不用算坐标）
curl -X POST -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
     -d '{"kind":"click","selector":"#submit","seed":31}' http://127.0.0.1:52137/input
```

## 8. 接 agent：MCP server

### 8.1 三种接法

```bash
# a) 让它自己按 discovery 顺序找（最省事；不要求应用已经起来）
node mcp/server.mjs --data-dir=F:/code/chrome/.userdata/agent

# b) 直接给地址
node mcp/server.mjs --url=http://127.0.0.1:52137?token=<token>

# c) 环境变量
MONITOR_CONTROL_URL='http://127.0.0.1:52137?token=<token>' node mcp/server.mjs
```

它是**纯 stdio**：stdout 上只有 JSON-RPC，诊断信息以 `isError` 回在工具结果里。
`npm run mcp` 等价。用 `--data-dir` 的接法**不要求应用已经起来**，应用后起也能接上，
重启换 token 也不用改配置。

### 8.2 注册到 Codex

```toml
[mcp_servers.monitor]
command = "node"
args = ["F:/code/chrome/mcp/server.mjs", "--data-dir=F:/code/chrome/.userdata/agent"]
```

或一条命令：`codex mcp add monitor -- node F:/code/chrome/mcp/server.mjs --data-dir=F:/code/chrome/.userdata/agent`

别的客户端用：

```json
{
  "mcpServers": {
    "monitor": {
      "command": "node",
      "args": ["F:/code/chrome/mcp/server.mjs", "--data-dir=F:/code/chrome/.userdata/agent"]
    }
  }
}
```

### 8.3 25 个工具

**观测**：`monitor_status` · `monitor_capabilities` · `monitor_requests` · `monitor_request` ·
`monitor_body` · `monitor_fetch_body` · `monitor_stats` · `monitor_timeline` ·
`monitor_scripts` · `monitor_script_source` · `monitor_console`

**执行与干预**：`monitor_evaluate` · `monitor_input` · `monitor_navigate` · `monitor_screenshot` ·
`monitor_dom_tree` · `monitor_dom_inspect` · `monitor_dom_highlight` ·
`monitor_rules_get` · `monitor_rules_set` · `monitor_rules_stats` · `monitor_probe`

**会话**：`monitor_sessions` · `monitor_switch_profile` · `monitor_clear`

参数与 HTTP 一一对应（`monitor_requests` 的过滤参数见 §7.2）。三条设计上值得知道的：

- `monitor_input` 收 **`selector`**，坐标换算工具自己做——不要自己算坐标
- `monitor_body` / `monitor_script_source` 是「大东西给引用不给正文」；要正文显式 `withData: true`
- Profile H 下 `monitor_evaluate` 返回**明确拒绝**，不是静默空值

### 8.4 接上之后先跑这条

```bash
npm run test:drill
```

只走 MCP stdio，不 import 项目内部模块，跑的每一步都是外部 agent 能跑的：
发现 → 查请求/详情/body → 读脚本与控制台 → 看 DOM → 截图 → 模拟点击 →
写规则并**验证拦截真的生效** → 跑探针 → 看会话 → 切 Profile（H 下 `evaluate` 被拒）→ 清理。
## 9. 排障

| 症状 | 多半是 | 怎么办 |
| --- | --- | --- |
| agent 连上了，但全是「死数据」 | 残留的 `control.json`（被硬杀的应用删不掉自己那份） | 检查 `startedAt`；验收类场景每次用独立 `MONITOR_DATA_DIR` |
| `/input` 每次调用都卡 ~5s，8 点轨迹要 40s | 被监控窗口被别的窗口盖住 → Chromium 按「不可见」节流渲染，鼠标事件回执被压到 5s | 别盖住它；确认启动参数里有抗节流三开关（`设计文档.md` D3）。**主进程健康检查正常、`netstat` 也看不出异常，只有窗口几何能证明** |
| 首屏请求一条都没抓到 | 没做到「先接管再放行」 | 被监控浏览器必须以 `about:blank` 启动，attach + enable 完再导航 |
| 同一行请求出现两次 | 同一个 target 被多个 session 各 enable 了一遍 | 见 `设计文档.md` §3.1 的 `primarySession` |
| 页面半死，CDP 一个错都不报 | Service Worker 卡在 install（对暂停中的 SW，`Network.enable` 永不回包） | 见 `设计文档.md` §3.1：SW 必须先放行再 enable |
| 某些请求没有请求头 / 响应头 | 那些请求在 Worker / SW 会话里，内核**不发** `Network.*ExtraInfo` | 内核行为。判据：受控页主线程请求 100% 有头 |
| 一条头都没有 | 同上，或者 `MONITOR_CAPTURE_BODIES=0` | 先确认是不是全在 worker 会话 |
| `evaluate` 返回「被拒绝」 | 当前是 Profile H（§3.4 红线，故意不可用） | 切回 L：`POST /sessions/profile {"profile":"L"}` |
| 脚本 tab 是空的 | Profile H（`Debugger` 只在 L 开）或 `MONITOR_CAPTURE_SCRIPTS=0` | 同上 |
| 三源关联率低、`ambiguous` 多 | `MONITOR_PROXY_WINDOW_MS` 太小 | 默认 1000；实测 50ms 时关联率只有 21.2% |
| 怀疑漏抓 | — | `npm run verify`：受控 origin 自记 access log 当真值逐条对照（判据：漏抓率 < 1%） |
| 抓不到浏览器自身的流量 | CDP 盲区（设计如此，`技术方案.md` §4 已声明） | 不计入漏抓 |
| 改了源码但行为没变 | 验收脚本跑的是 `out/main/index.js` | `npm run build` |
| 每次都采到不一样的请求集合 | 复用了同一个 profile（Service Worker 会留脏） | 每次用独立 `MONITOR_DATA_DIR` |
| 端口被占 / 撞车 | — | `MONITOR_API_PORT` 指定；开发时的端口分区见 `设计文档.md` §9.3 |
| 收工后还有 chrome 残留 | 被监控的是真 Chrome，不是 Electron 的子进程 | `taskkill /F /IM electron.exe /T` **和** `/F /IM chrome.exe /T` |
| 怀疑 pipe 有问题 | — | `node scripts/probe-pipe.mjs` |
| 想让采集队列落盘 | 硬杀进程会丢队列 | 用 `MONITOR_AUTO_QUIT_MS` 或 `MONITOR_QUIT_FILE` 体面收工 |

## 10. 打包成可执行文件

```bash
npm run dist:win     # 产物在 dist/
```

产出两个东西：

| 文件 | 用途 |
| --- | --- |
| `dist/ChromiumMonitor-<版本>-portable.exe` | **主交付**：单文件，双击即用，运行时自解压到临时目录 |
| `dist/win-unpacked/` | 免安装目录版，排查打包问题用这个（不用等自解压） |

**包里自带 Node 运行时**，所以目标机器**不需要装 Node**（存储/代理/控制服务都是 node 子进程，
且要 `node:sqlite`）。那个 `node.exe` 是构建时从 npmmirror 下到 `.buildtools/node/` 的，
已加进 `.gitignore`；换机器重新构建前先确认它有 85MB 左右。

**仍然需要目标机器装了 Chrome** —— 被监控的必须是真 Chrome，内置浏览器就不是真 Chrome 了。
找不到时用 `CHROME_PATH` 指定。

几个打包相关的坑（都已处理，改配置时别踩回去）：

- `control/` `mcp/` `storage/` `proxy/` 是**独立 node 子进程**，必须走 `extraResources` 摊在
  `resources/` 下，**不能打进 asar** —— 子进程读不了 asar 里的文件
- 代码里定位这些目录统一走 `src/main/paths.ts`，别再用 `join(__dirname, '../..')`
- 打包后数据目录是 `%APPDATA%/ChromiumMonitor`（跟着 `productName` 走），和开发态的
  Electron userData 不是同一个

## 11. 已知限制与注意事项

完整列表见 `README.md` 的「已知限制」。日常使用最需要记住的几条：

- **Worker / SW 会话没有请求头**：`Network.*ExtraInfo` 内核不发。受控页实测主线程请求 100% 有头
- **`/input` 返回 ≠ 页面已收到**：还会继续投递 ~150ms。要立刻读结果就留 ~200ms
- **抗节流三开关的代价**：页面被遮挡时仍按「可见」跑（rAF、定时器不降频）。
  和真人在前台用浏览器一致，但「靠后台节流做手脚」的页面能看出这点差异
- **必须有图形界面**：窗口得真的显示出来，页面才有正确的 `outerWidth` / `visibilityState`。
  纯无桌面的容器里这条会退化
- **开代理会换掉出站 TLS 指纹**：被拦截的 host 由抓包端去连，指纹是 Node 的而不是 Chrome 的
  JA3/JA4。所以代理默认关着——要对齐得上 uTLS 那一套（未做）
- **大 body 改写只覆盖拿得到 `content-length` 的响应**：chunked / 流式（含 SSE）不改
- **响应头改写拿不到 body 时放弃**：CDP 没有「只改响应头」的命令
- **规则动作只有网络与注入两类**：拟人化输入目前是面板/API 手动触发，还不是规则动作
- **body 采集计数有 +1 漂移**：大 body 超限放行后页面立刻收工的竞态，在容差内
- **切 Profile 是收工重启**，不是热切：启动参数、domain 白名单、采集侧 `Debugger` 通道都钉在
  浏览器生命周期上，热切做不干净

### 还没做的功能

只有两项，且都不影响上面任何一项日常使用：

- **P4**：Profile H 的自编译 + 二进制 patch。真阻塞是机器缺 Windows SDK；缺 Chromium 源码树属资源投入
- **P7**：自建 content 壳 / mojo 无痕通道。它是「P4 不够才立项」的条件项

另有一个**未决的设计决策**（不是待办）：H 现在不开 `Runtime` / `Debugger`，

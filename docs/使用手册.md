# 使用手册 · Chromium 监控容器

> 面向使用者和 agent。目标是「照着做就能用起来」。
> 想改代码看 `docs/设计文档.md`，想接 agent 看本文 §7–§8 与 `docs/AI-控制面.md`。

## 1. 这是什么

一个本机的页面观测 + 干预工具：用**真实的 Chrome** 打开目标站点，把它的请求、响应、
body、JS 源码、DOM、console、cookie 与站点存储（localStorage / IndexedDB / 缓存 / Service Worker）、
以及「页面实际收到了什么」全记下来，并且可以动手改包、注入脚本、模拟真人点击输入、直接增删这些站点资源。同时对外开一个只绑 `127.0.0.1` 的 HTTP API 和一个 MCP server，让 agent 能全面控制。

三个关键特征，决定了它和普通抓包工具的差别：

- **零污染**：承载目标页面的是独立进程的真 Chrome，不是 Electron；CDP 走 pipe，没有监听端口
- **先接管再放行**：启动时先停在 `about:blank`，等所有 target 都 attach 完才导航，首屏请求一条不漏
- **判据在页面侧**：改包有没有生效、点击有没有真点到，都由页面自己回报，不采信工具自述

## 2. 前置条件

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 系统 Node | **22+** | 存储进程用 `node:sqlite`；`MONITOR_NODE_PATH` 可指定 |
| Chrome | 已安装 | 不设则自动查找；`CHROME_PATH` 可指定 |
| 平台 | Windows / macOS / Linux | 本机开发环境是 Windows 11 + PowerShell 5.1 |
| 图形界面 | **有头环境** | 窗口必须真的显示出来，页面才有正确的 `outerWidth` / `visibilityState` |

> PowerShell 5.1 不支持 `&&`，多条命令用 `;` 连接。

## 3. 五分钟跑起来

```bash
# 1) 装依赖
npm install

# 2) 跑起来（开发模式，默认打开 https://example.com）
npm run dev

# 换个目标站点、换个 Profile、指定数据目录
$env:MONITOR_URL='https://example.com'; $env:MONITOR_PROFILE='L'; $env:MONITOR_DATA_DIR='F:\tmp\m1'; npm run dev
```

跑构建产物（验收脚本用的就是这条路）：

```bash
npm run build
npx electron .
```

> `electron.exe` 是 **GUI 子系统程序**，在 PowerShell 里直接 `.\node_modules\electron\dist\electron.exe .`
> 会**立刻返回**（PowerShell 不等 GUI 程序），看起来像「没反应」。要么用 `npx electron .`，
> 要么用 `Start-Process -FilePath .\node_modules\electron\dist\electron.exe -ArgumentList '.' -Wait`。

**数据目录**默认是 Electron 的 `userData` 路径，找起来不直观。建议一开始就显式指定
`MONITOR_DATA_DIR`——规则文件、数据库、profile、`control.json` 全在里面。

**怎么体面收工**：

- `MONITOR_AUTO_QUIT_MS=60000` —— 60 秒后自动退出（会把采集队列落盘）
- `MONITOR_QUIT_FILE=F:\tmp\stop` —— 该文件一出现就退出（比死等秒数精确）
- 直接关窗口也行。**别用 `taskkill` 硬杀**，队列里没落盘的东西会丢，还会留孤儿 chrome
- 收工要杀干净时，记得被监控的是真 Chrome：`taskkill /F /IM electron.exe /T` **和** `taskkill /F /IM chrome.exe /T`

## 4. 界面速览

窗口用的是自绘标题栏（系统标题栏不显示）。顶栏从左到右是：

- **状态区**：品牌、连接状态灯（待机 / 启动内核中 / 建立连接中 / 已连接 / 出错）、
  当前 Profile、内核版本、body 采集模式
- **指标区**：本次采集 / 命中筛选 / 已落库 / body / 脚本 / 附着的 target 数
- **全局动作**：`吸附`（把浏览器贴到控制窗口旁边，见 §5.8）、`刷新`、
  `清空`（只清本次采集缓冲，库里的历史不动）、`数据目录`
- **窗口三键**：最小化 / 最大化（还原）/ 关闭 —— 和原生窗口一样

标题栏空白处可以拖动窗口，双击标题栏等于最大化 / 还原。

### 4.1 工作区是自由的

面板区是一个**自由工作区**：1–4 栏并排（也可以上下叠），每栏自己选用哪块面板，栏与栏之间可拖。

- 右上角三个按钮：`＋ 分栏`（再加一栏，最多 4 栏）、`⇔ 左右` / `⇕ 上下`（所有栏换排布方向）、
  `⟲ 复位`（回到默认的「请求列表 + 请求详情」）
- 每栏栏头那颗胶囊下拉框就是「这一栏显示什么」，**十五个面板全在里面**（瀑布图、统计、脚本、规则、
  控制台、环境、DOM、会话、事件流、WebSocket、接口画像、调用图、站点资源都在）；栏头的 `✕` 关掉这一栏
  （只剩一栏时不显示，免得工作区空掉）
- 拖分隔条改大小；**双击分隔条**把各栏均分。一栏最窄留 160px，拖到头就顶住，不会把谁挤没
- 摆好的布局记在 `<数据目录>/ui-settings.json`，下次开窗口还是这个样子
- `?tab=`（`MONITOR_UI_TAB`）指定的开局面板**优先于**这份落盘布局

### 4.2 十五个面板

| 面板 | 看什么 / 干什么 |
| --- | --- |
| **请求列表** | 全量请求，按类型 / 域名 / 状态过滤。10 万条以内虚拟滚动不掉帧 |
| **瀑布图** | 网络分段（排队 → DNS → TCP → TLS → TTFB → download）+ 关联状态色标 + 详情入口 |
| **请求详情** | 选中那条请求的全部证据，内部四个 tab：**概览** / **头** / **发起链** / **body** |
| **脚本** | 所有已加载 JS（含内联 / `eval` / Worker / SW），可搜索、可格式化。**仅 Profile L** |
| **统计** | 按类型 / 域 / 状态聚合，含大小与耗时 |
| **规则** | 规则编辑器，改完实时生效；命中统计也在这 |
| **控制台** | 执行 JS 表达式 + 页面 console 实时回流（500 条环形缓冲）。**仅 Profile L** |
| **环境** | 当前 Profile、能力矩阵、探针报告、指纹明细、拟人化输入入口 |
| **DOM** | DOM 树 + 命中样式 + 事件监听器，可高亮节点 |
| **会话** | 实例列表、Profile 切换、存储分区与各表行数 |
| **事件流** | 导航 / console 告警 / 异常 / 下载 / JS 对话框 / WS 生命周期，按 kind 分组；**对话框在这里应答** |
| **WebSocket** | WS / SSE 的帧：左边连接、右边帧正文（`sent` = 页面发出），二进制显示真实字节数 |
| **接口画像** | 三页签：接口聚类画像（状态码 / 耗时 / 参数与请求体字段分布 / 节奏）、契约回归、导出（HAR / JSONL / 资源镜像） |
| **调用图** | 两页签：请求调用图（边权重 + 功能簇）、关联分析（共享响应体 / 跳转链 / 共享参数 / 页面 → 域） |
| **站点资源** | Cookie / 本地存储 / IndexedDB / 缓存 / Service Worker / 快照六个页签：左边域列表、右边明细；顶栏能筛选、只看扫过的、刷新扫描、拍快照、看 cookie 画像。**cookie 罐一直在轮询，站点存储是点了才扫**（见 §5.10） |

默认摆的是「请求列表 + 请求详情」两栏 —— 看起来和从前一样，但现在它们可以被拆开、换位置、换内容。

## 5. 常用任务

### 5.1 看某个页面发了哪些请求

开应用默认就是「请求列表 + 请求详情」两栏，左边那块。要精确定位就用过滤：URL 子串、域名、状态（`2xx` / `404` 这种写法也行）、
类型（`XHR` / `Document` / `Script` / `Fetch`）。

### 5.2 看一条请求的全部证据

列表里点一行，右侧详情：

- **概览** —— 时序、大小、状态、body 摘要
- **头** —— 请求头 / 响应头
- **发起链** —— initiator 调用栈
- **body** —— 正文（大 body 默认只给摘要 + hash，正文在库里被 LRU 管着）

开了代理（`MONITOR_PROXY=1`）还会多出「三源关联 / 上游 IP / TLS 套件 / 网络分段」。

> 注意：**Worker / Service Worker 会话不发头**，落在这些会话里的请求看不到 req / resp headers。
> 这是内核行为，不是 bug。

### 5.3 改包 / 拦截 / mock

**规则** 面板写规则，或直接编辑规则文件（默认 `<数据目录>/rules.json`）。匹配维度有
URL / host / method / resourceType / frameUrl / status / 正则等；动作分两类：

- 网络类：block、redirect、改请求头、改响应头、改请求体、改响应体、delay、mock
- 注入类：按 `document_start` / `document_ready` 注入脚本

改完**实时生效**，不需要重启。命中情况在**规则**面板的统计里看。

两条要记住的边界：

- **大 body 改写**只下沉「拿得到 `content-length`」的响应；chunked / 流式（含 SSE）不改
- 带 `resourceType` / `frameUrl` / `targetType` 约束的 body 规则**不下发到代理**（代理拿不到这些信号），
  日志会报条数

### 5.4 模拟真人点击 / 输入

**环境**面板有输入入口，但更常用的是给 selector 让工具自己算坐标：

```bash
# 直接给选择器，不用自己算坐标（页面自己算，不受缩放/滚动影响）
POST /input  { "kind": "click", "selector": "#submit", "seed": 31 }
POST /input  { "kind": "type",  "selector": "#search", "text": "hello", "seed": 21 }
POST /input  { "kind": "move",  "x": 900, "y": 600, "seed": 20260919 }
POST /input  { "kind": "scroll","x": 640, "y": 400, "deltaY": 600 }
```

轨迹是贝塞尔弧线 + 变速 + 停顿 + 错字回退，**同 seed 可复现**。

> **`/input` 返回 ≠ 页面已经收到**：事件会在浏览器队列里排队，实测返回后还会继续投递 ~150ms。
> 要「点完立刻读结果」，留 ~200ms，或把读取并进同一次 `/evaluate`。

### 5.8 让浏览器贴着控制窗口（窗口吸附）

顶栏那个 `吸附` 按钮。点一下：控制窗口让到屏幕一侧，浏览器贴到另一侧，两个窗口中间留 8px，
之后**你拖控制窗口、缩放它，浏览器都跟着走**（最小化也会跟着最小化）。

- 蓝底 `吸附 右` / `吸附 左` = 已经吸上了，标签是浏览器所在的那一侧
- 旁边的 `⇄` = 换到另一侧
- 黄底 = 开着但没吸上，鼠标停上去会说原因（最常见的是浏览器还没起来 / 已经被关掉）
- 再点一次 = 关掉。**浏览器会停在原地**，不会被挪回它原来的位置
- 开关状态会落盘（`<数据目录>/ui-settings.json`），下次启动自动恢复

几个要知道的：

- 它**不是把浏览器嵌进这个应用**：浏览器还是独立进程、独立窗口，我们只是同步它的位置尺寸。
  这么做是为了不动 Chrome 的窗口几何 —— 抗节流方案依赖几何正确（见设计文档 D3 / D9）。
- 浏览器**关掉再起来**（或者 Chrome 自己重建窗口）会自己重新吸上，不用手动点。
- 浏览器窗口有最小宽度（≈515 DIP）。你要是把控制窗口拉得比屏幕还宽，浏览器会溢出屏幕边缘，
  但它绝不会反过来压住控制窗口。
- 只有 Windows 有这功能（靠 `win/dock-helper.ps1` 调 Win32 API），其它平台按钮是禁用状态。
- 验收：`npm run test:dock`（会真的挪动、缩放、最小化窗口，跑的时候别碰鼠标）。

### 5.9 实时分析：事件流 / WebSocket / 接口画像 / 调用图 / 契约回归

四块新面板（栏头下拉框里都在），刷新的方式都是**增量游标**：拉过的不再拉，看到的永远是新的。

- **事件流**：导航 / console 告警 / 未捕获异常 / 下载 / JS 对话框 / WebSocket 生命周期，
  按 kind 分条，`warn` / `error` 高亮。**JS 对话框要在这里点「放行」或「取消」** ——
  不应答页面就一直卡着（面板上会显示那条待应答的）。
- **WebSocket**：左边连接列表、右边帧。`sent` 是页面发出去的、`received` 是服务端推过来的；
  二进制帧按**真实字节数**显示，帧正文可搜。
- **接口画像**：三个页签 —— *接口画像*（按「方法 + 主机 + 路径模板」聚类：调用次数、状态码分布、
  p50/p95、query 与请求体字段分布、调用节奏；点开看字段分布与**响应结构**）、
  *契约回归*（拍基线 → 改东西 → 再跑 → 看 diff）、*导出*（HAR / JSONL / 资源镜像）。
- **调用图**：两个页签 —— *调用图*（谁触发了谁、边权重、互相牵动的功能簇）、
  *关联分析*（共享响应体 / 跳转链 / 共享参数 / 页面 → 域）。

命令行上做同一件事：

```bash
# 事件流：拿一次 nextSince，之后只拉新增
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/events?since=0&limit=200"

# WebSocket：先列连接，再按连接看帧
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/ws/connections"
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/ws?requestId=<id>&limit=100"

# 接口画像 / 调用图 / 关联
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/endpoints?sort=calls&minCalls=2"
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/graph"
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/relations"

# 契约回归：先拍基线，改完东西再 diff
curl -X POST -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
     -d '{"label":"baseline-v1"}' http://127.0.0.1:52137/contracts
curl -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/contracts/1/diff"

# 导出：文件落在 <数据目录>/exports/，返回的是绝对路径
curl -X POST -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
     -d '{"includeBodies":true}' http://127.0.0.1:52137/export/har
```

要**推**而不是拉，用 SSE（服务端按 `interval` 毫秒查库，有新的就推一帧）：

```bash
curl -N -H "authorization: Bearer $TOKEN" "http://127.0.0.1:52137/events/stream?since=0&interval=500"
```

它和轮询读的是同一份数据，不会出现「推的」和「查的」不一致。

下载（页面上点了会下载的东西）落在 **`<数据目录>/downloads/`**，不再往你的下载夹里丢；
`MONITOR_DOWNLOAD_DIR` 可以改，设成空串就交回浏览器默认位置。

### 5.10 看 / 管站点资源（Cookie 与站点存储）

「站点资源」面板（栏头下拉框里选）管的就是**我们拉起的那个浏览器**攒下来的东西：cookie 罐，以及
每个域的 localStorage / sessionStorage / IndexedDB / Cache Storage / Service Worker 注册。

**两个时间概念要先分清**，这是这一块最容易踩的地方：

- **cookie 罐**很便宜，采集侧一直 **5s 轮询**一遍（收到 `Set-Cookie` 再 250ms 防抖补一次），库里那份基本跟得上
- **站点存储**每个域要连问好几条 CDP，所以是 **点了才扫**：面板上的「刷新扫描」，或者 `POST /sites/scan`

> 判据类的用法（「点了登录之后 cookie 变了吗」）**先扫一次再看**，别拿陈旧快照下结论。

```bash
# 扫一遍（不带 origin = 最近有流量的前 20 个域）
POST /sites/scan  { "limit": 20 }
POST /sites/scan  { "origin": "https://example.com" }

# 域清单 / 单域明细 / cookie 罐
GET /sites?onlyScanned=1
GET /sites/detail?origin=https://example.com
GET /cookies?domain=example.com&sort=sentCount

# 往罐里写一条（自动化里「先登好再测」那一步）/ 按条件删
POST   /cookies  { "name": "sid", "value": "x", "domain": "example.com", "path": "/" }
DELETE /cookies?name=sid&domain=example.com
DELETE /cookies?crossSite=1        # 清第三方 cookie

# 改站点存储 / 删库 / 删缓存 / 注销 SW（都会自动重扫该域）
POST /sites/storage       { "origin": "https://example.com", "area": "local", "action": "set", "key": "k", "value": "v" }
POST /sites/idb/delete    { "origin": "https://example.com", "name": "sd_db" }
POST /sites/cache/delete  { "origin": "https://example.com", "name": "sd_cache" }
POST /sites/sw/unregister { "scopeURL": "https://example.com/" }

# 快照：拍基线 → 改 → 再拍 → 比出「多了什么」
POST /sites/snapshots { "label": "before-login" }
GET  /sites/snapshots
GET  /sites/snapshots/1/diff
```

**删 cookie 必须给条件**（`name` / `domain` / `host` / `url` / `path` / `crossSite` 至少一个）：
一个都不给会被**拒绝**（`{ "ok": false, "deleted": 0 }`，HTTP 仍是 200）。这是故意的 —— 免得手滑清空整个罐。

MCP 侧对应 16 个工具：`monitor_cookies` · `monitor_cookie_stats` · `monitor_cookie_set` ·
`monitor_cookie_delete` · `monitor_sites` · `monitor_site_detail` · `monitor_site_scan` ·
`monitor_site_clear` · `monitor_site_storage_edit` · `monitor_site_idb_delete` ·
`monitor_site_cache_delete` · `monitor_site_sw_unregister` · `monitor_site_snapshot` ·
`monitor_site_snapshots` · `monitor_site_snapshot_diff` · `monitor_site_snapshot_delete`。
验收：`npm run test:sitedata`（30 项，判据逐条对 CDP 真值）。

## 6. 环境变量速查

最常用的（完整表在 `README.md` 的「环境变量」一节）：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `MONITOR_URL` | 起始 URL | `https://example.com` |
| `MONITOR_PROFILE` | `L` 或 `H` | `L` |
| `MONITOR_DATA_DIR` | 数据目录（库 / 规则 / profile / control.json / exports / downloads / screenshots） | Electron userData |
| `MONITOR_DOWNLOAD_DIR` | 被监控页面下载的文件落到哪；设成**空串** = 交回浏览器默认位置 | `<数据目录>/downloads` |
| `MONITOR_HEADLESS` | `1` 走 headless | 关 |
| `CHROME_PATH` | 指定内核 | 自动查找 |
| `MONITOR_AUTO_QUIT_MS` | N ms 后体面收工 | 0（不自动退） |
| `MONITOR_QUIT_FILE` | 出现该文件即收工 | — |
| `MONITOR_PROXY` | `1` 开本地代理（DNS/TLS 时序 + 大 body 改写） | 关 |
| `MONITOR_API` | `0` 关掉 AI 控制面 | 开 |
| `MONITOR_API_PORT` | 控制服务端口 | `0`（系统分配） |

| `MONITOR_BODY_TYPES` | 采集 body 的 resourceType 范围（收窄成 `Document,Script,Stylesheet,XHR,Fetch` 可省开销） | 空 = 全部类型 |
| `MONITOR_SCRIPT_MAX_KB` | 单个脚本上限 | 2048 |
| `MONITOR_UI_TAB` | 开局选中哪个面板（`list`/`waterfall`/`scripts`/`stats`/`rules`/`console`/`env`/`dom`/`sessions`）。给 list / waterfall 开局是「它 + 详情」两栏，其它面板单栏铺满；**优先于落盘的布局**。不设这个变量就恢复上次摆的布局 | `list` |

## 7. HTTP API 手册

### 7.1 先发现地址和 token

控制服务绑 `127.0.0.1`，端口与 token 由应用写在数据目录的 `control.json`：

```json
{ "port": 52137, "token": "…", "pid": 12345, "startedAt": 1789820000000 }
```

```powershell
$info = Get-Content "$env:MONITOR_DATA_DIR\control.json" | ConvertFrom-Json
$base = "http://127.0.0.1:$($info.port)"
$h = @{ authorization = "Bearer $($info.token)" }
```

> **残留的 `control.json` 是个经典坑**：被硬杀的应用删不掉自己那份，agent 会连上一次的死数据。
> 判据是 `startedAt`，只认本次启动之后写的。

| `/workspaces/:id/rules` | `{ set: RuleSet, expectedVersion?, idempotencyKey? }` | 指定工作区覆盖式保存，返回任务结果 |

| `/sessions/profile` | `{ profile: "L" \| "H" }` | 切 Profile（收工重启，约几十秒） |
| `/clear` · `/console/clear` | — | 清采集缓冲（计数同时归零，库里的历史不动）/ 清 console |
| `/contracts` | `{ label, sampleLimit, domain }` | 给接口契约拍快照，回 `{ id, endpoints, truncated }` |
| `DELETE /contracts/:id` | — | 删掉一份快照 |
| `/export/har` · `/export/jsonl` · `/export/bodies` | `{ query, includeBodies, maxRows, dir }` | 导出 HAR / JSONL / 资源镜像，回落盘**绝对路径**与计数 |
| `/sites/scan` | `{ origin?, limit?, cookies? }` | **点了才扫**：连问 CDP 把这一域（或最近有流量的前 limit 个域，默认 20）的站点存储读回来落库；`cookies:false` 跳过罐对账 |
| `/cookies` | `{ name, value, domain? \| url?, path, secure, httpOnly, sameSite, expires \| maxAge }` | 往浏览器罐里写一条（`maxAge: 0` = 立刻作废；不给 `maxAge`/`expires` = 会话 cookie） |

| `/sites/snapshots` | `{ label? }` | 拍一份站点快照（拍之前先扫一遍，免得基线陈旧） |
| `DELETE /sites/snapshots/:id` | — | 删掉一份快照 |
| `/dialog` | `{ accept, promptText }` | 应答 JS 对话框 —— 不应答页面一直卡着 |

## 8. 接 agent：MCP server

### 8.1 三种接法


## 9. 排障

| 症状 | 多半是 | 怎么办 |
| --- | --- | --- |
| agent 连上了，但全是「死数据」 | 残留的 `control.json`（被硬杀的应用删不掉自己那份） | 检查 `startedAt`；验收类场景每次用独立 `MONITOR_DATA_DIR` |
| `/input` 每次调用都卡 ~5s，8 点轨迹要 40s | 被监控窗口被别的窗口盖住 → Chromium 按「不可见」节流渲染，鼠标事件回执被压到 5s | 别盖住它；确认启动参数里有抗节流三开关（`设计文档.md` D3）。**主进程健康检查正常、`netstat` 也看不出异常，只有窗口几何能证明** |
| 首屏请求一条都没抓到 | 没做到「先接管再放行」 | 被监控浏览器必须以 `about:blank` 启动，attach + enable 完再导航 |
| 同一行请求出现两次 | 同一个 target 被多个 session 各 enable 了一遍 | 见 `设计文档.md` §3.1 的 `primarySession` |
| 页面半死，CDP 一个错都不报 | Service Worker 卡在 install（对暂停中的 SW，`Network.enable` 永不回包） | 见 `设计文档.md` §3.1：SW 必须先放行再 enable |
| 某些请求没有请求头 / 响应头 | 那些请求在 Worker / SW 会话里，内核**不发** `Network.*ExtraInfo` | 内核行为。判据：受控页主线程请求 100% 有头 |
| 一条头都没有 | 同上，或者 `MONITOR_CAPTURE_BODIES=0` | 先确认是不是全在 worker 会话 |
| `evaluate` 返回「被拒绝」 | 当前是 Profile H（§3.4 红线，故意不可用） | 切回 L：`POST /sessions/profile {"profile":"L"}` |
| 脚本面板是空的 | Profile H（`Debugger` 只在 L 开）或 `MONITOR_CAPTURE_SCRIPTS=0` | 同上 |
| 三源关联率低、`ambiguous` 多 | `MONITOR_PROXY_WINDOW_MS` 太小 | 默认 1000；实测 50ms 时关联率只有 21.2% |
| 怀疑漏抓 | — | `npm run verify`：受控 origin 自记 access log 当真值逐条对照（判据：漏抓率 < 1%） |
| 抓不到浏览器自身的流量 | CDP 盲区（设计如此，`技术方案.md` §4 已声明） | 不计入漏抓 |
| 改了源码但行为没变 | 验收脚本跑的是 `out/main/index.js` | `npm run build` |
| 面板里的 cookie / 存储比浏览器里少 | 库里的那份是**上一轮轮询（或上一次扫描）的快照** | 点「刷新扫描」，或 `POST /sites/scan` |
| 删 cookie 返回 `ok:false` 但 HTTP 是 200 | 一个条件都没给（应用层故意拒绝，免得清空整个罐） | 至少给 `name` / `domain` / `host` / `url` / `path` / `crossSite` 之一 |
| 每次都采到不一样的请求集合 | 复用了同一个 profile（Service Worker 会留脏） | 每次用独立 `MONITOR_DATA_DIR` |
| 端口被占 / 撞车 | — | `MONITOR_API_PORT` 指定；开发时的端口分区见 `设计文档.md` §9.3 |
| 收工后还有 chrome 残留 | 被监控的是真 Chrome，不是 Electron 的子进程 | `taskkill /F /IM electron.exe /T` **和** `/F /IM chrome.exe /T` |
| 怀疑 pipe 有问题 | — | `node scripts/probe-pipe.mjs` |
| 想让采集队列落盘 | 硬杀进程会丢队列 | 用 `MONITOR_AUTO_QUIT_MS` 或 `MONITOR_QUIT_FILE` 体面收工 |

## 10. 打包成可执行文件

```bash
npm run dist:win     # 产物在 dist/
```

产出两个东西：

| 文件 | 用途 |
| --- | --- |
| `dist/ChromiumMonitor-<版本>-portable.exe` | **主交付**：单文件，双击即用，运行时自解压到临时目录 |
| `dist/win-unpacked/` | 免安装目录版，排查打包问题用这个（不用等自解压） |

**包里自带 Node 运行时**，所以目标机器**不需要装 Node**（存储/代理/控制服务都是 node 子进程，
且要 `node:sqlite`）。那个 `node.exe` 是构建时从 npmmirror 下到 `.buildtools/node/` 的，
已加进 `.gitignore`；换机器重新构建前先确认它有 85MB 左右。

**仍然需要目标机器装了 Chrome** —— 被监控的必须是真 Chrome，内置浏览器就不是真 Chrome 了。
找不到时用 `CHROME_PATH` 指定。

几个打包相关的坑（都已处理，改配置时别踩回去）：

- `control/` `mcp/` `storage/` `proxy/` 是**独立 node 子进程**，`win/dock-helper.ps1` 是主进程
  spawn 的 PowerShell 脚本 —— 它们都得走 `extraResources` 摊在 `resources/` 下，
  **不能打进 asar**（子进程读不了 asar 里的文件）
- 代码里定位这些目录统一走 `src/main/paths.ts`，别再用 `join(__dirname, '../..')`
- 打包后数据目录是 `%APPDATA%/ChromiumMonitor`（跟着 `productName` 走），和开发态的
  Electron userData 不是同一个

## 11. 已知限制与注意事项

完整列表见 `README.md` 的「已知限制」。日常使用最需要记住的几条：

- **Worker / SW 会话没有请求头**：`Network.*ExtraInfo` 内核不发。受控页实测主线程请求 100% 有头
- **`/input` 返回 ≠ 页面已收到**：还会继续投递 ~150ms。要立刻读结果就留 ~200ms
- **抗节流三开关的代价**：页面被遮挡时仍按「可见」跑（rAF、定时器不降频）。
  和真人在前台用浏览器一致，但「靠后台节流做手脚」的页面能看出这点差异
- **必须有图形界面**：窗口得真的显示出来，页面才有正确的 `outerWidth` / `visibilityState`。
  纯无桌面的容器里这条会退化
- **开代理会换掉出站 TLS 指纹**：被拦截的 host 由抓包端去连，指纹是 Node 的而不是 Chrome 的
  JA3/JA4。所以代理默认关着——要对齐得上 uTLS 那一套（未做）
- **大 body 改写只覆盖拿得到 `content-length` 的响应**：chunked / 流式（含 SSE）不改
- **响应头改写拿不到 body 时放弃**：CDP 没有「只改响应头」的命令
- **规则动作只有网络与注入两类**：拟人化输入目前是面板/API 手动触发，还不是规则动作
- **body 采集计数有 +1 漂移**：大 body 超限放行后页面立刻收工的竞态，在容差内
- **切 Profile 是收工重启**，不是热切：启动参数、domain 白名单、采集侧 `Debugger` 通道都钉在
  浏览器生命周期上，热切做不干净
- **站点资源是「对账」不是「实时镜像」**：cookie 罐 5s 轮询（收到 `Set-Cookie` 再 250ms 防抖），
  站点存储点了才扫。要下判据先 `POST /sites/scan`；删 cookie 必须给条件，一个不给会被拒
- **窗口吸附只有 Windows 可用**：靠 `win/dock-helper.ps1` 调 Win32 API，其它平台按钮是禁用状态。
  它也不把浏览器嵌进应用 —— 浏览器始终是独立进程，只同步位置尺寸，关掉时还是停在原地
- **响应体默认全类型采集**：图片 / 字体 / 媒体也会被拦一次，媒体重的页面能感觉到。只关心接口就用
  `MONITOR_BODY_TYPES=Document,Script,Stylesheet,XHR,Fetch` 收窄；超 `MONITOR_BODY_MAX_KB`（256KB）
  的仍然只有摘要 + hash

### 还没做的功能

只有两项，且都不影响上面任何一项日常使用：

- **P4**：Profile H 的自编译 + 二进制 patch。真阻塞是机器缺 Windows SDK；缺 Chromium 源码树属资源投入
- **P7**：自建 content 壳 / mojo 无痕通道。它是「P4 不够才立项」的条件项

另有一个**未决的设计决策**（不是待办）：H 现在不开 `Runtime` / `Debugger`，
而 P4 的效果判据恰恰需要这两个 domain 的泄漏场景才有判别力。
详见 `docs/P4-P7-待办与阻塞.md`。

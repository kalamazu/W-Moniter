## 背景与目标

浏览器下载目前只有目录配置和部分网络记录，文件完成、失败、最终路径与正文引用没有成为工作区证据。本任务将可见下载转成可校验、可导出、可追溯原请求的 Artifact。

## 范围

- 要实现：监听下载开始/进度/完成/取消；以工作区归属登记原始名、安全文件名、MIME、大小、hash、requestId 与 ContentRef；支持范围读取、完整导出和存在性校验。
- 要修改的边界：BrowserRuntime/Controller 下载事件、artifact repository、content 导入通道、工作区证据/UI/HTTP/MCP。
- 非目标：不自动执行下载文件；不在本卡实现病毒扫描或任意文件系统浏览。

## 依赖与风险

- 前置任务：T-003、T-008、T-011、T-012。
- 数据/兼容性/安全风险：文件名路径穿越、同名覆盖、部分文件被误当完整；UI/Agent 不得接受未校验的原始绝对路径。
- 需要 ADR 的取舍：下载目录与 ContentStore 是单副本、硬链接还是双副本，以及删除/回收语义。

## 验收标准

- 用户或 Agent 流程：页面触发小文件、100 MiB 与重复同名下载，界面显示进度与最终证据；重启后可校验和导出。
- 自动化测试：覆盖 Content-Disposition、blob URL、重定向、取消、断网、同名与二进制；源站 hash、落盘文件和 ContentStore 三方一致。
- 失败与边界行为：临时文件、取消和短写不得发布完整 Artifact；原文无法获取时仍保留下载事件及原因。

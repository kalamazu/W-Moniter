## 背景与目标

现有 WebSocket 帧仍有 payload 截断边界，SSE 长响应没有可持续读取的原文对象。本任务建立长连接内容的分段、游标、完整性和 ContentStore 引用，使显示预览上限不再成为原文存储上限。

## 范围

- 要实现：WS 收/发帧的完整 payload 引用、方向/时间/序号；SSE 活跃片段、事件边界、游标读取与正常/中断结束；UI/HTTP/MCP 按页及按范围读取。
- 要修改的边界：Collector/代理事件、content 协议、stream repository、实时面板与证据导出；列表预览与原文引用分开。
- 非目标：不在本卡实现 WS/SSE 脚本重放、断言或智能分析；不保证内核未向 CDP/代理暴露的流量。

## 依赖与风险

- 前置任务：T-010、T-012。
- 数据/兼容性/安全风险：长连接无自然大小上限；必须使用配额、保留策略与可见缺口，不能静默覆盖旧帧。
- 需要 ADR 的取舍：活跃 stream manifest 的可读性、封口 hash 语义与保留单元。

## 验收标准

- 用户或 Agent 流程：在连接进行中分页读已采集片段；断开后仍能按时间线还原方向、内容和缺口。
- 自动化测试：WS 文本/二进制、超大单帧、1 万帧、有序收发；SSE 心跳、多行 data、无限流、中断与重连；origin/page/终端三方计数和 hash 可对照。
- 失败与边界行为：二进制不做损失性文本转换；过载、断连、丢帧或乱序必须留 gap 事件，不得报 complete。

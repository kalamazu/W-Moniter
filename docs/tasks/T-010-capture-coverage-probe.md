# T-010：全量采集路径与缺口真值矩阵

- 状态：可认领
- 蓝图映射：M1 §4.2、§13.2；E04
- 优先级：P0

## 背景与目标

T-004～T-005 已让常规非流式响应进入 ContentStore，但 SSE、WS、大上传、缓存、Service Worker、下载及失败边界尚无完整的独立真值。先确定每条来源路径能提供哪些原始字节、何时不能提供，避免把“已记录缺口”误称“全量采集”。

## 范围

- 要实现：新增确定性 origin/流/上传 fixture 与 `scripts/probes/capture-paths.mjs`；在现有 Fetch、CDP 可用路径及代理路径上分别测原文 hash、页面消费、内存峰值、时序、表示方式、缺口原因。给出响应、上传、WS/SSE、下载、缓存/SW 的覆盖矩阵，按 Profile 和浏览器版本保存证据。
- 要修改的边界：测试 fixture、采集观测/统计、`docs/architecture/capture-coverage.md`（或同等能力账本）；不改写正在运行的 Fetch 仲裁语义。
- 非目标：本任务不以调大缓冲区充当解决方案，不承诺所有路径已补齐，也不在探针阶段静默切换生产采集来源。

## 依赖与风险

- 前置任务：T-004；复用 T-005、T-008 的证据与校验接口，二者的独立验收尚待完成。
- 风险：某些 CDP 接口可能改变页面消费或只提供解码后的表示；代理路径可能改变出站时序。实验必须保留原站真值并标明结果是推断还是实测。
- 取舍：标准路径无法覆盖的类型，应提交采集适配/浏览器定制候选 ADR，不得降低蓝图“完整采集”目标。

## 验收标准

- 用户或 Agent 流程：可查询一条请求的来源、原文 hash/大小、表示方式与缺口原因；矩阵中的每个结论能追到 fixture 和测试输出。
- 自动化测试：固定大小二进制响应、未知长度流、大上传、WS/SSE、缓存/SW、下载至少各有一例；测试同时核对服务端收到的真实字节与浏览器页面是否正常消费，并记录内存峰值。
- 失败与边界：超时、短写、断连不得标 `complete`；不稳定/未覆盖项目保留为明确未决，不用跳测变绿。

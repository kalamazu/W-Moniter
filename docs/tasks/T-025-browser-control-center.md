## 背景与目标

控制能力散落在导航、输入、DOM、截图和下载接口中，缺少稳定对象模型与面向用户的浏览器工作台。本任务把标签页、窗口、Frame、DOM、上传下载、等待和对话框收敛成可观察、可取消的控制中心。

## 范围

- 要实现：Tab/Window/Frame 树，新建/关闭/导航/刷新/分组，DOM 定位与截图，受管文件上传，下载任务，事件条件等待，对话框处理和动作时间线。
- 要修改的边界：BrowserRuntime、目标与 document generation、稳定引用、控制 Action、BrowserWorkbench 与权限确认。
- 非目标：不允许网页或 Agent 通过上传动作读取未授权任意文件；不伪造系统级输入能力。

## 依赖与风险

- 前置任务：T-001、T-022、T-024。
- 风险：旧元素引用操作新页面、目标焦点漂移、导航与人类操作并发冲突、文件路径逃逸。
- 需要 ADR：浏览器/标签动作串行化、对象代次和人类接管租约。

## 验收标准

- UI 与 Agent 可在明确 browser/tab/frame 上完成一条“打开页面→定位→上传→提交→等待下载→取证”流程。
- 覆盖 iframe、重定向、弹窗、对话框、页面刷新、旧元素拒绝、取消和人类接管。
- 所有副作用动作有目标、代次、开始/完成证据，不随 UI 当前焦点偷换对象。

# T-015：工作台信息架构与响应式窗口控制

## 背景与目标

现有界面把 target、工作区证据、布局按钮、全局动作和窗口三键平铺在顶部；窗口变窄时信息互相挤占，target 标签会折行侵占主区，且无统一的功能发现、命令和设置入口。将其收敛为面向人类与 Agent 的工作台：稳定的窗口控制、活动栏/视图导航、按需展开的运行时上下文、全局命令入口和明确的设置区，同时保留用户已有的多窗格布局。

## 范围

- 要实现：固定不被内容挤走的最小化/最大化/关闭区；活动栏与侧栏；运行时 target 抽屉；命令面板（面板、布局、设置动作）；设置抽屉；窗格焦点与键盘可达性；工作区条的紧凑化。
- 要修改的边界：`src/renderer/src` 的工作台组件、样式与布局偏好字段；必要的界面偏好解析。
- 非目标：不伪造浏览器 Cookie 编辑、请求重放、插件安装/启停或新后端能力；不删除既有面板与多分栏。

## 依赖与风险

- 前置任务：T-000、T-005、T-009、T-013、T-014 已提供工作区与证据摘要。
- 数据/兼容性/安全风险：界面偏好需要对旧文件向后兼容；窗口三键所在区域必须保持 `no-drag`；不在 UI 中泄露 Cookie/正文。
- 需要 ADR 的取舍：新增工作台导航与可持久化的界面偏好，见 ADR-0008。

## 验收标准

- 用户或 Agent 流程：窄窗口下窗口三键始终可见；target 仅显示摘要，详情从运行时抽屉查看；可从活动栏、侧栏和命令面板打开全部既有面板；可用快捷键打开/关闭命令面板并触发动作；有可达的设置入口。
- 自动化测试：类型检查、生产构建、布局持久化回归，以及覆盖命令与响应式结构的渲染层测试。
- 失败与边界行为：无 target、无工作区、窗口很窄、布局满 4 栏时均不遮挡主窗口操作；未知旧偏好字段安全忽略。

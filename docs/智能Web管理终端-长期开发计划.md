# 智能 Web 管理终端：产品目标与长期开发计划

版本：规划草案 v1.1 ｜ 更新：2026-09-22 ｜ 基线：`F:\code\chrome`，提交 `0579ff4`

v1.1 重点变更：将“工作区作为持久的浏览器状态容器”提升为核心架构，新增工作区状态机、站点登录台账、浏览器插件清单、历史资料归属、快照恢复与隔离验收，并相应扩大 M0/M2 排期。这里的插件指受控浏览器的扩展，不是终端自身或 Agent 的插件。

本文用于后续立项、拆分开发任务和阶段验收。它描述目标产品与实施顺序，不表示这些能力已经实现。工期是规划估算，不是交付承诺。

## 1. 产品目标

把现有 Chromium 监控工具发展为一个常驻的**智能 Web 管理终端**：管理自己的浏览器、账号环境和工作区；完整保存访问过程中可采集的请求与资源；理解站点的页面、接口、存储和交互关系；编辑、重放和测试请求；用脚本和 Agent 编排这些能力；让人能通过清晰的可视化界面观察、检查、修改和接管。

产品的一条完整主线是：

> 打开工作区 → 启动或连接受控浏览器 → 访问站点并完整记录 → 形成站点档案 → 选择请求或页面动作 → 修改、重放、编排测试 → 对比结果 → 保存可复用资产 → 交给 Agent 继续执行并在人类界面查看证据。

### 1.1 已确定的方向

1. **全量采集是默认产品目标。** 不因响应大于 256KB、图片、字体、媒体等原因主动跳过正文；大内容通过流式写盘和按需读取解决，不能用默认不采集代替工程实现。
2. **工作区是持久的浏览器状态容器，也是产品中心。** 每个工作区记住自己的浏览器身份、登录过哪些站点、登录验证状态、安装了哪些插件、打开的页面、网络配置与历史资料。工作区之间独立保存和恢复；关闭浏览器不丢失工作区，切换工作区不混用身份。浏览器、站点、代理、环境变量、请求集合、脚本、测试与报告均有明确归属。
3. **浏览器既可观察，也可操作。** 用户能管理标签页、Cookie、站点存储、网络环境、页面动作和下载，并看到操作的真实结果。
4. **请求是可执行资产。** 从一次访问中捕获的请求，可以编辑、重放、多次运行、参数化、串联、断言和回归。
5. **能力对 Agent 友好，显示对人类友好。** Agent 调用结构化动作；人类使用编辑器、资源树、图表、差异视图和运行时间线。两者使用相同数据和执行引擎。
6. **分析必须能回到证据。** 每一个接口结论、站点关系和 Agent 判断都能链接到请求、资源、页面状态或测试结果。

### 1.2 “全量”和“完全控制”的工程含义

“全量”指对已接管浏览器、已覆盖协议与采集时段内的内容，默认保留完整数据。它不能含糊地等同于“请求列表里有一行”。请求元信息完整、请求正文完整、响应正文完整、实时消息完整，要分别度量。

长连接保存截至当前时刻的连续片段，并标明仍在接收；断流保存已收到的数据与中断原因。磁盘不足、进程崩溃、浏览器接口不提供某类内容时，必须显式报告缺口，不能标为采集完成。完整 hash 只能对真正读完的内容计算；只知道 Content-Length 不能声称已有完整 hash。

“完全控制”落实为可发现、可组合、可验证的能力矩阵。第一优先级是终端自己启动和管理的浏览器；连接已有浏览器作为明确的接入模式，不能假设任意普通 Chrome 都可无条件接管。对接管前的流量、未开放接口、受保护内容和系统级能力，返回具体原因及可行替代方案。内核扩展用于补已证实的缺口，不以“不可检测”作为产品主轴。

## 2. 当前基础与实际缺口

以下是本次代码检查和前轮受控验收的基线，不是对任意站点、长期负载的保证。

| 领域 | 当前基础 | 距目标的缺口 | 后续处理 |
| --- | --- | --- | --- |
| 请求采集 | CDP 多 target、请求元信息、部分 body、脚本采集 | 大 body 会跳过；长流和完整性口径不足 | 重建正文存储及流式采集链路 |
| 数据存储 | SQLite、正文去重、查询与导出 | 正文容量策略、长期历史、崩溃恢复需要重新设计 | 元数据与内容文件分离，增加归档与恢复 |
| 工作区 | 1–4 栏、15 个面板、布局保存 | 布局不是工作区；缺持久浏览器状态、站点登录台账、插件清单、隔离与恢复 | 引入 Workspace 状态容器、状态机和预设工作台 |
| 浏览器插件 | 当前未核实有完整插件管理链路 | 缺插件版本、权限、配置归属、期望/实际状态及兼容性验证 | 建立扩展清单与按浏览器版本验证的管理适配层 |
| 浏览器管理 | 一个主 Controller、Profile 切换、导航与输入 | 历史实例不等于多浏览器管理；缺显式标签页定位及完整生命周期 | BrowserManager、Tab/Frame 定位、持久 Profile |
| Cookie / 存储 | 已有读写删除 API、扫描、快照及部分 UI | Cookie 写 API 存在，但人类新增/编辑/导入流程不完整；存储细节能力有缺口 | 补完整编辑器与读回验证 |
| 代理 | 本地 MITM 及部分改写能力，环境变量配置 | 缺用户可管理的上游代理、认证、分流、诊断与作用域 | 独立代理配置中心 |
| 请求重放 | 未见成体系的请求重放服务及产品入口 | 缺编辑器、执行语义、历史、次数、参数与脚本 | 新建重放及测试域 |
| 分析 | 接口画像、调用图、关联、契约与导出 | 缺资源库、跨运行比较、可纠正归类、明确推断置信度 | 建立站点档案与资源索引 |
| Agent | HTTP / MCP 已有广泛能力 | 工具走通不代表任务可靠；缺稳定对象定位、异步任务、并发冲突及长任务恢复 | 统一动作契约与任务系统 |
| 人类交互 | 技术面板覆盖广 | 四栏窄宽时不可读；编辑与观察混排；专业字段密集 | 工作台、全宽编辑器、上下文联动与渐进披露 |
| 发布 | Windows 打包产物可运行，已内置 Node | 当前版本号不足以证明产物来源；升级、迁移、回滚、长稳测试待完善 | 建立可追溯发布与兼容矩阵 |

前轮证据：类型检查/构建通过，核心专项 144 项、全量冒烟 129 项、打包分析面 15 项通过。10 万条列表本机抽样为 83.85fps。这些证明已覆盖路径能运行，不足以证明全量 body、重放、长期稳定性或完整工作流程已经完成。

## 3. 对旧设计的明确调整

后续实施遇到下列冲突时，以本文的新产品方向为准，并在对应阶段同步修改旧文档，避免保留两份互相矛盾的规格。

| 原有取舍 | 新方向 | 原因 |
| --- | --- | --- |
| body 超限跳过或只留元信息 | 无按大小跳过的默认策略；预览上限与采集上限分离 | 完整资源研究、重放与回归依赖正文 |
| 会话规则全局共享 | 工作区模板 → 浏览器/运行局部覆盖，执行时冻结版本 | 支持 A/B，避免两个实验互相改配置 |
| 省略 session 就操作当前 active | 多对象环境下写动作明确目标；兼容调用在执行前固定目标 | 人类切页不能改变 Agent 正在操作的对象 |
| 工作区只是私有布局 | 工作区拥有持久浏览器状态；登录、插件、配置、历史共同归属，人类布局单独保存 | 人类和 Agent 能回到同一个有记忆、可检查的浏览环境 |
| 浏览器关闭就结束会话 | 浏览器进程只是工作区的一次运行；身份和资料长期保留 | 再次打开能继续工作，历史状态不冒充当前在线状态 |
| 用 Cookie 有无推断已登录 | 记录账号线索、站点验证证据和检查时间，区分未确认、有效、过期、需交互 | 避免错误身份参与重放和自动化 |
| 不做会话模板、恢复、跨会话分析 | 纳入多浏览器、实验和比较阶段 | 智能终端需要长期积累，而非每次从零开始 |
| Profile H 优先限制能力 | 能力与采集/调试配置明确分开，能力不足可提示切换 | 深度浏览器控制比统一“隐蔽”标签更重要 |
| 单条请求与面板是主组织方式 | 站点、资源、请求集合、实验、工作流共同组织 | 用户需要完成任务，而非只阅读数据 |
| 工具调用成功就算完成 | 动作执行、结果读回、业务断言分层返回 | HTTP 200、CDP 回执不能代替实际效果 |

### 4.1 主导航

| 工作台 | 用户主要任务 | 核心显示方式 | 可调用能力 |
| --- | --- | --- | --- |
| 总览 | 恢复并了解一个工作区的完整浏览环境 | 工作区卡片、登录站点、插件清单、历史资料、状态变化、任务进度 | 状态快照、打开/休眠/恢复、检查登录、配置对账、任务管理 |

| 代理与环境 | 配网络与账号环境 | 路由图、配置表单、连接诊断 | 配置版本、代理测试、应用及回读 |
| 自动化与 Agent | 执行跨能力任务 | 流程、运行时间线、证据卡片、人类接管 | 工作流执行、等待事件、取消、恢复 |

### 4.2 人类界面的约束

- 左侧是工作区与业务对象，顶部是当前浏览器/标签页上下文；下方是长任务和采集健康。具体底层 domain 名放到高级详情。
- 默认采用主内容加按需详情；重放、脚本和存储编辑使用足够宽的工作台。保留自由分栏，但按面板最小可读宽度约束，提供聚焦/最大化和保存预设。
- 请求详情一键进入重放、资源、接口或关联页面；测试结果一键返回其请求、正文和脚本版本。
- 不同视图共用明确的筛选范围，并显示“全部工作区 / 当前浏览器 / 当前运行 / 当前站点”等范围标签。
- 大列表虚拟滚动，大正文分块读取；“预览前 N 字节”必须能继续读取或下载完整文件，不改变已保存的数据。
- 草稿自动保存；切工作台、改布局、重连、重启后可恢复。数据刷新保留选中项、滚动位置及编辑内容。
- 错误、空数据、仍在采集、历史快照和真实当前状态分别显示；不能用空白面板掩盖后端错误。
- 可视化必须支持点击筛选和回到明细。关系图之外提供列表和搜索，防止站点复杂后变成不可读的图团。
- 工作区首页给出“这个环境是谁、能做什么、上次做到了哪里”：账号标签、站点登录检查时间、插件版本及生效状态、标签页与历史资料、代理出口、最后检查点。关闭状态仍能浏览历史。
- 切换 A/B 工作区时，身份、插件与历史一起切换；其他工作区的后台任务有独立标记。跨工作区搜索或比较必须显式选择范围，不把资料混到当前环境中。

## 5. 统一对象与架构

### 5.1 对象模型

| 对象 | 含义及归属 |
| --- | --- |
| Workspace | 持久浏览器状态容器；拥有身份、站点登录台账、插件清单、配置版本、资料、任务与检查点；默认一个主身份，可显式增加独立身份 |
| BrowserProfile | 归属于一个 Workspace 的持久浏览器身份与磁盘目录，拥有 Cookie/存储/扩展数据；默认不跨工作区共享可变目录，与监测配置 Profile L/H 分开命名 |
| BrowserInstance | 一次运行中的浏览器进程；引用 Workspace、BrowserProfile、实际网络配置 |
| Tab / Frame / Target | 操作与观测的目标；明确区别标签页、iframe、worker，不能把所有 target 当成可交互页面 |
| CaptureSession | 一段观测历史，可按任务/时间切分；不等于浏览器身份，也不等于数据库单行实例 |
| Request / Exchange | 一次实际交换；关联重定向链、发起者、采集来源、运行及完整性状态 |
| Body / ResourceVersion | 不可变正文与资源版本；同内容可去重，但保留每次 URL、header、时间、身份与来源关系 |
| Site / Endpoint | 站点及接口索引；自动归类允许纠正和版本化 |
| RequestTemplate / Collection | 可编辑请求模板及集合；从原始请求派生，原始证据不覆盖 |
| Environment / SecretRef | 环境变量与秘密引用；测试/生产等环境独立，运行时解析 |
| Script / Workflow / TestSuite | 有版本的脚本、步骤与断言，可复用、可通过 UI 或 Agent 执行 |
| Run / Step / Artifact | 一次任务及其步骤、输出证据；包括重放、扫描、测试、导出、Agent 任务 |
| SiteIdentity / AuthObservation | 站点与身份的关联；保存账号标签、登录状态证据、检查时间、有效期及检查方式，不把明文凭据放进状态摘要 |
| ExtensionBinding | 工作区身份下的浏览器插件；记录 ID、来源、期望/实际版本、启用状态、权限、配置引用及兼容结果 |
| WorkspaceCheckpoint | 工作区配置、资料引用与可恢复浏览器状态的版本化检查点；说明一致性等级与不可恢复项 |
| WorkspaceEvent / StateProjection | 持久状态变更日志与可重建摘要；关联事件序号、对象版本、操作者及证据 |

所有资源使用稳定 ID。日志、任务、API 和界面统一引用 `workspaceId / browserId / tabId / captureId / runId`，请求 ID 不只依靠可能跨实例重复的 seq。origin 保留 scheme/host/port；Cookie 再保留 domain/path/name/partition 等真实身份字段。

### 5.2 服务分层

```text
人类工作台        HTTP / MCP / CLI / 外部 Agent
      \              /
       统一动作与查询服务（契约、对象定位、配置版本、任务状态）
          ├─ 工作区与浏览器管理
          ├─ 采集与代理
          ├─ 请求重放与测试
          ├─ 脚本与工作流运行器
          ├─ 站点、资源与接口分析
          └─ 元数据存储 + 正文文件存储 + 搜索索引
```

Electron 主进程保留窗口和编排；大正文不通过渲染进程搬运，不在主进程做大型解析。正文通道、脚本运行、索引和测试任务与界面隔离。可先使用本机进程与 SQLite，不为了将来的规模提前引入分布式系统。

先统一契约和目标定位，再按领域从现有 Controller 渐进拆分。保留兼容适配与旧数据库迁移；避免一次性重写全部已验证模块。

### 5.3 并发与人机协作

- 查询可以并行；导航、输入、Profile/代理变更等会影响页面状态的动作，按浏览器或标签页有序执行。
- 人类正在编辑的请求与 Agent 运行中的模板各有版本，运行冻结输入；保存冲突返回差异，不后写覆盖。
- Agent 的目标始终固定，不跟随 UI 当前选择。人类可以观察、停止任务或接管控制。
- 页面导航后旧元素引用失效，返回重新定位所需信息；不能继续在新页面用旧坐标或旧 nodeId 操作。
- 自动重试只用于有明确语义的步骤；提交、付款、删除等可能有外部副作用的请求不能因网络超时自动重复。

### 5.4 核心设计：工作区是浏览器的持久状态容器

#### 5.4.1 用户模型与隔离关系

一个工作区对应一套可持续使用的浏览环境。例如，“日常工作”保存工作账号、常用插件和项目历史；“接口实验”保存测试账号、调试插件、独立代理与测试资料。同一站点可以在两处分别登录不同账号，切换视图不会改变另一处的 Cookie、插件配置或正在执行的任务。

默认每个工作区有一个主 BrowserProfile，用户打开工作区就回到这个身份。高级场景允许在工作区内增加独立身份做 A/B 比较；每个身份都单独列出登录与插件状态，不把它们合成一个模糊的“工作区已登录”。同一身份可有多个窗口和标签页，但同一磁盘资料目录最多由一个浏览器写进程占用。

```text
工作区 A（持久）                    工作区 B（持久）
├─ 主浏览器身份 A                   ├─ 主浏览器身份 B
│  ├─ 站点/账号/登录证据            │  ├─ 独立站点/账号/登录证据
│  ├─ Cookie/站点存储               │  ├─ 独立 Cookie/站点存储
│  └─ 浏览器插件/权限/配置          │  └─ 独立插件/权限/配置
├─ 运行中的浏览器/标签/任务         ├─ 自己的浏览器/标签/任务
├─ 历史请求/资源/下载/接口/笔记      ├─ 自己的历史资料
└─ 状态事件/检查点/工作台布局        └─ 自己的状态事件/检查点
```

可以按内容 hash 共享底层不可变资源文件以去重，但资料引用和查询范围必须按工作区隔离。复制资料会创建目标工作区的新引用及来源关系；删除 A 不能删掉 B 仍在引用的文件。默认隔离是产品数据与进程隔离，不宣传为抵御恶意扩展或本机管理员的操作系统安全沙箱。

#### 5.4.2 工作区保存哪些状态

| 状态面 | 保存内容 | 权威来源与更新方式 |
| --- | --- | --- |
| 身份 | Profile ID、浏览器版本、账号标签、站点映射 | 工作区配置 + 实际浏览器身份；账号线索带来源 |
| 站点登录 | 最近确认的账号、状态、验证方式/时间、挑战提示 | 站点适配器的会话检查或页面证据；浏览器 Cookie 仅作为线索 |
| 浏览器插件 | ID、版本、来源、启用/权限、配置及数据引用 | 期望清单 + 经支持管理接口观察到的实际状态 |
| 页面现场 | 窗口/标签 URL、标题、分组、选中页、可恢复导航信息 | 浏览器事件与定期对账；敏感表单、内存对象不默认序列化 |
| 网络环境 | 代理、路由、采集/改写规则、期望及实际配置版本 | 终端配置、执行回执、出网诊断 |
| 历史资料 | 访问记录、请求/正文、资源版本、下载、接口、脚本、测试、截图、笔记 | 不可变采集证据 + 工作区资产索引，附采集起止及缺口 |
| 任务 | 正在执行/暂停/结束的任务、输入版本、检查点及结果 | 任务服务与动作日志；区分本地执行和远端业务结果 |
| 健康 | 进程、连接、存储、采集完整性、恢复错误 | 运行探测与存储确认，不能由上次保存的 running 字段推定 |

普通访问信息按采集期间逐步建立台账；以前未记录的浏览器历史可以单独导入并标来源，但不能据此补造过去的网络正文。页面内容、历史笔记和 Agent 结论分别存储，以免摘要覆盖原始资料。

#### 5.4.3 使用分层状态机，避免把所有状态塞进一个枚举

工作区采用生命周期状态机；浏览器运行、站点登录、插件、任务、采集健康各自独立。工作区运行中时，某个站点可能登录过期、某插件等待重启、某任务已完成，这些并不意味着整个工作区都要进入“失败”。

| 工作区状态 | 含义 | 进入/离开条件 |
| --- | --- | --- |
| `creating` | 创建独立身份、目录、配置和索引 | 成功后 `closed`；失败记录原因进入 `error` |
| `closed` | 浏览器已关闭，持久资料可浏览 | 打开进入 `opening`；归档进入 `archived` |
| `opening` | 获取身份锁、启动浏览器、连接、采集接管、配置对账 | 核心链路就绪进入 `running`；启动失败进入 `error` |
| `running` | 浏览器可用，任务按实际能力执行 | 保存检查点/休眠/关闭进入 `checkpointing`；丢失控制进入 `recovering` |
| `checkpointing` | 停止接收冲突写动作、排空队列并保存可恢复状态 | 在线逻辑检查点完成后回 `running`；休眠/关闭完成后进入 `suspended` 或 `closed`；失败按浏览器是否仍可用回 `running` 或 `error` |
| `suspended` | 已保存现场并释放浏览器进程资源 | 恢复进入 `opening`；不是冻结了原来的进程内存 |
| `recovering` | 核对进程、锁、存储、半完成动作并尝试重连/恢复 | 可用后 `running`；未恢复则 `closed` 或 `error`，记录恢复结果 |
| `error` | 核心启动/恢复失败，历史仍可读 | 显式重试进入 `opening`/`recovering`；检查后允许回 `closed` |
| `archived` | 历史只读，不能运行浏览器或变更身份 | 解除归档回 `closed` |

首次版本不把“删除”混成关闭状态。删除工作区走独立任务，展示影响范围，依据共享正文引用处理数据；保存中或运行中不能直接移除目录。

以上生命周期以默认主身份为入口；增加多个身份后，每个身份单独维护运行状态，工作区汇总就绪、退化和错误原因。局部身份失败不覆盖其他身份的可用状态；工作区级休眠/关闭必须等所有所属身份的写进程退出才能完成。在线逻辑检查点不是整个浏览器在同一瞬间的原子快照，应记录各部分采样时间及一致性范围。

关键不变量：

- `closed / suspended / archived` 不存在该工作区仍持有写锁的受管浏览器进程；确认进程退出后才完成状态转换。
- `running` 要有实际探测证据；终端重启先进入对账流程，旧 PID 还需核对创建时间、资料目录和本次运行标识，防止 PID 复用。
- 状态转换经单一命令入口校验前置版本和合法目标状态；并发 open/close/restore 只能串行，不能同时操作目录。
- 不允许归档状态自动接收写任务；某子能力不可用时返回具体缺口，界面显示 degraded 原因，避免误报全部功能可用。
- 每次浏览器重建生成新的运行代次 `generation`；旧 Tab/Frame/元素/任务引用必须重新绑定，不能碰巧命中新对象。

**切换工作区只切界面焦点。** A 的后台任务是否继续，按显式后台策略执行。打开 B 不自动关闭 A；“切换”“休眠 A”“关闭 A”是不同动作。恢复标签页需显示哪些页面会重新请求网络，优先延迟加载；不自动重交表单或恢复执行未确认的外部写动作。

#### 5.4.4 站点登录台账与状态机

登录状态按 `workspaceId + profileId + siteId + accountContext` 管理，保留具体 origin/SSO 关联。一个身份中同站可能存在租户、多账号选择器和分区上下文，不能单用域名或 Cookie 名判断账号。

采用两个独立维度：`lastConfirmedState` 表示最近可靠结论，`checkState` 表示该结论是否新鲜。这样网络不可达不会把“曾验证已登录”错误覆盖成“已退出”。

| 最近可靠结论 | 进入条件 |
| --- | --- |
| `unknown` | 没有足够证据；只发现 Cookie/令牌也保持未确认 |
| `authenticated` | 站点会话接口或可解释页面证据确认有效；有账号标识则记录，并标时间 |
| `signed_out` | 观察到明确退出动作的结果或可靠未登录检查 |
| `expired` | 站点明确表示认证失效；不能根据任意接口 401 就统一判整个站点过期 |
| `challenge_required` | 明确观察到二次验证、账号选择或交互登录要求 |

`checkState = never_checked / checking / fresh / stale / unavailable`。检查过期、Cookie/相关存储变化、身份恢复、登录相关跳转触发待复核；网络错误设置 unavailable，保留旧结论但不再当作当前认证保证。一个站点的失效不影响其他站点的记录。

通用观察器记录线索；特定站点适配器提供可选的会话检查和账号提取；用户也可标注“这是工作账号”。手工标注必须与自动验证分开。后台检查采用被动优先及低频、可配置方式，避免探测本身造成退出、限流或大量网络请求。

Agent 运行涉及账号的任务时，可以要求“指定账号、fresh 认证证据”；不满足就返回 `auth_unknown / auth_expired / interaction_required` 等原因及 UI 入口。检测不足不等于禁止用户手动浏览，也不自动替用户换账号。

#### 5.4.5 浏览器插件状态与配置对账

每个 BrowserProfile 维护插件清单：`extensionId / name / source / desiredVersion / observedVersion / desiredEnabled / observedEnabled / permissions / configRef / lastCheckedAt`。期望配置和当前状态分开，记录 `pending / applying / in_sync / drifted / unsupported / error`；需要重启时另标记 `restartRequired`。

- 工作区首页可查看、筛选、启停及进入插件设置；版本、来源、权限变化保留历史。能否安装/禁用/导出配置由浏览器版本及管理适配能力报告。
- 技术验证分别覆盖浏览器已有插件枚举、可支持来源的安装、卸载/启停、配置持久化、重启读回。不得假设任意 Chrome 都可通过 CDP 自动完成所有扩展管理。
- 扩展自动升级、用户在浏览器里修改设置时，观察实际差异并显示，不能仍显示旧的绿色同步状态。用户可采用实际配置或再次应用期望配置。
- 插件可能改请求、页面或网络代理；记录可观察的实际配置与流量，冲突有证据才归因。未知来源改动显示待确认，不把一切变化归到终端规则。
- 插件私有存储、外部程序、浏览器账号同步及登录状态不保证可通用导出。备份清单列出已包含/未包含/需重新安装项；控制不了的自动同步不能作为已经实现的隔离保证。

#### 5.4.6 持久化、对账、检查点与恢复

工作区配置是“希望怎样”，浏览器与站点是“实际怎样”，事件日志记录“发生过什么”，首页摘要是这些证据的投影。不能仅根据一次按钮点击把期望值当成实际值。

状态变更与审计事件在元数据事务中提交，带单调 `eventSeq`、对象版本、发生/观察时间、操作者、运行代次和证据引用；通过事务后的事件出口通知 UI/Agent。事件重投使用 ID 去重。大正文沿用 M1 文件/manifest 协议，不把文件写入假装成 SQLite 同一原子事务；重启时对未提交片段和失效引用做修复。

浏览器事件优先，定期低频对账补插件/存储等盲区。历史观察只供解释，恢复不通过重放历史操作日志再登录、安装插件或发送请求。

检查点分两级：

| 类型 | 可以承诺 | 不能据此承诺 |
| --- | --- | --- |
| 逻辑检查点 | 配置版本、标签列表、资产引用、已支持 Cookie/存储快照及任务边界 | 任意插件内部数据、所有页面内存、未提交表单的完整恢复 |
| 关闭后一致备份 | 确认浏览器退出、采集/存储 flush 后，对受管资料目录及相关索引做版本化备份 | 跨机器解密成功、站点服务端登录永不失效、旧浏览器兼容所有新版本资料 |

恢复流程：核对版本/密钥依赖 → 获取恢复命令独占权 → 协调停止受影响任务、关闭目标浏览器并确认目录无写进程 → 保存当前可回退检查点 → 恢复到临时目录并校验 → 切换资料目录 → 启动并对账 → 登录状态标 stale 后按需验证 → 展示恢复结果。失败保留可回退副本；检查点固定引用的资源不被后台清理。整个流程持有目录管理锁，禁止同时启动浏览器或执行另一轮恢复。

复制工作区默认复制结构、非秘密配置和选择的历史资料，创建新身份；“带身份复制”是独立显式选项，说明复制范围与不能迁移的内容。不能依靠硬链接共享可变 profile 文件。即便本地副本独立，同一服务端账号上的修改仍可能互相影响，任务应显示实际账号。

#### 5.4.7 人类首页与 Agent 接口

首页固定包含：工作区状态和上次使用时间、浏览器身份卡、登录站点列表（账号/验证时间/证据）、插件清单（版本/同步状态）、最近标签和访问、历史资源/请求/报告、后台任务、最近检查点及状态变化时间线。登录标记可点开来源；插件或账号变化能定位到时间及运行。

Agent 通过 `workspace.describe / open / suspend / close / checkpoint / restore / events`、`site.authStatus / verify`、`extensions.list / apply / reconcile` 等拟议动作读写同一套状态服务。接口名称在 M0 定稿，不代表现有实现。

`workspace.describe` 默认返回摘要与资源引用，包含状态版本、运行代次、数据新鲜度、站点登录摘要、插件漂移、未完成任务和可执行动作；不默认返回 Cookie 值、token 或整个浏览器资料。用户明确任务范围内的秘密读写走专门动作。Agent 可据此判断“该去哪个工作区、哪个账号、需不需要恢复”，人类能在相同对象上继续操作。

## 6. 核心能力设计

### 6.1 全量正文与实时流

**分清三件事：采集、保留、展示。** 默认采集完整内容；保留策略独立配置；展示可以只预览。用户没有配置淘汰策略时，不因内部 LRU 限额静默删掉仍被历史请求引用的唯一正文。

实现方向：

1. SQLite 保存索引与来源，正文进入分块文件存储，边接收边计算 hash，完成后原子提交 manifest。未完成的数据保留临时记录与已提交片段。
2. 用小型技术验证选择主采集路径。优先验证在不消耗页面正文、不重复发请求的前提下，将浏览器可提供的内容写盘；代理验证边转发边落盘。不能直接把 `Fetch.getResponseBody` 的上限调到几 GB，也不能假设接管 Fetch 响应流后浏览器还能自动照常消费。
3. CDP 与代理各保留来源信息，补齐缓存命中、Service Worker 合成响应、下载、worker、跨域 iframe 等盲区。代理不是唯一真值；必要时规划扩展/内核适配补缺，不能把未覆盖内容从统计中静默排除。
4. 区分传输编码内容与解码内容。代理看到的压缩载荷、CDP 返回的解码正文不能混成同一个“原始字节”。是否同时保存两份由可用来源决定；HTTP 头重建和重放使用正确的编码语义。
5. 请求正文也要全量：文本、二进制、multipart 文件上传、未知长度上传分别验证；不能只完成响应大文件就宣布全量采集完成。
6. SSE 按持续字节/事件追加；WebSocket 保留方向、时间、连接与重连、浏览器可提供的消息/帧语义；媒体保存实际获取的分片和 Range 信息。未被浏览器请求的影片部分不算已捕获，受保护内容不伪称已解码。
7. 磁盘吞吐跟不上时有界缓存与背压；磁盘不足或写入失败时，按工作区策略暂停采集/任务或保留失败状态，向用户报告缺口。有限磁盘无法保证无限长流永久完整。

建议完整性字段：`pending / receiving / complete / interrupted / unavailable / evicted_by_policy`，附 `capturedBytes`、`expectedBytes?`、`source`、`representation`、`reason` 与片段范围。已结束请求不可同时显示 complete 和截断；实时流不伪造最终长度。

验收：256KB、10MB、100MB、1GB 正文与上传的字节/hash 对照；无 Content-Length、压缩、大并发、Range、缓存、SW、下载、SSE、WS 全覆盖；正文增大时内存不按正文总量线性增长；进程中断后可识别已保存范围并恢复索引。重启后不能声称自动补回从未捕获的原网络数据。

### 6.2 工作区与浏览器控制

- 工作区以 §5.4 的持久状态容器为核心，保存站点登录台账、浏览器插件、身份数据、网络环境、历史资料、任务、检查点与布局；历史可离线检索，关闭浏览器不删除这些资料。
- 多浏览器各有独立身份目录；同一 Profile 不允许两个写进程抢占。工作区间不共享可变身份目录；带身份复制按 §5.4 的显式流程执行，复制后两份目录独立。
- 登录、插件、采集和任务各自记录状态及新鲜度；工作区总览聚合展示。实际浏览器状态与期望配置定期对账，插件更新或手工登录变化能被识别。
- 标签页/窗口新建、关闭、切换、导航、前进后退、刷新、页面等待、iframe 定位、DOM/可访问性快照、点击、输入、选择、滚动、拖拽、上传、下载、对话框和截图逐步补齐。
- 每个动作提供完成条件，如“URL 匹配”“元素可见”“请求完成”“下载落盘”，减少固定等待。
- 权限、时区、语言、视口、网络模拟、缓存与 Service Worker 策略作为浏览器环境配置；显示需要重启还是即时生效。
- “关闭标签”“结束采集”“关闭浏览器”“退出终端”区分；重启恢复工作区和草稿，运行恢复以幂等性及已记录的检查点为依据。

### 6.3 Cookie 与站点存储

- Cookie 表支持新增、编辑、批量导入/导出、按站点/身份/分区筛选、查重复和过期；覆盖 HttpOnly、Secure、SameSite、expiry、domain/path、partition 等字段。
- 保存前显示作用范围与字段错误，保存后从浏览器读回，再由受控请求验证实际发送行为。写入成功不等于必然被任何请求携带，也不等于恢复登录。
- localStorage/sessionStorage 提供键值/JSON 编辑；IndexedDB 提供库、对象仓库、索引、分页记录及选定记录编辑；CacheStorage 可查看条目和完整正文；Service Worker 可查看 scope、状态并执行生命周期操作。
- 存储快照版本化，支持差异与有范围的恢复；明确哪些类型支持可靠恢复。恢复运行中页面时先协调页面活动并读回验证，不能承诺还原服务端状态。
- Cookie/正文中的秘密本机可按任务使用；共享报告与导出可选择脱敏，秘密配置使用系统凭据存储或加密存储，避免把值写入普通配置日志。

### 6.4 代理与网络环境

区分三个对象：上游出网代理、本地采集/改写代理、请求干预规则。界面展示实际路径，例如“浏览器 → 本地采集 → 上游 SOCKS5 → 目标站点”，不能只给一个难以判断含义的“代理开启”。

计划能力：直连、系统代理、HTTP/HTTPS 上游、SOCKS5、认证、bypass、按域路由、DNS 行为说明、连通性与出口验证、证书配置、配置版本及每运行引用。PAC 支持作为独立适配项，明确它的执行环境与支持范围。

直连回退必须显式配置；指定代理不可用时，不静默绕过去。切换配置时交代现有连接是否保持、是否新建网络上下文或重启浏览器。测试报告记录实际代理链与执行器，防止两个实验暗中用了不同出口。

### 6.5 请求重放工作台

从抓到的请求创建可编辑模板，保留原始记录，支持 URL/query/method/重复 header/文本、JSON、表单、multipart、二进制 body。支持 cURL/HAR 导入、资源文件引用、环境变量、身份选择及发送前有效配置预览。

**两个执行模式必须显式区分：**

| 模式 | 用途 | 必须呈现的语义 |
| --- | --- | --- |
| 浏览器上下文重放 | 尽量使用指定浏览器身份和页面上下文 | 受 Cookie、SameSite、CORS、受限 header、SW、页面环境影响；不能承诺任意原始报文逐字重现 |
| 独立 HTTP 重放 | 精确编辑请求、参数测试、批量运行 | 网络执行器独立；Cookie jar、代理、TLS/协议行为与浏览器可能不同，按明确策略同步身份 |

每次执行记录：模板版本、解析后的环境、执行器、身份策略、原请求引用、实际发出的请求、重定向链、响应、正文引用、耗时和差异。默认一次发送就是一个明确执行；失败可能“服务器已收到但结果未返回”，需有 `outcome_unknown` 状态。

捕获的 Cookie 头、实时 Cookie jar、手工 Cookie 值的优先级必须显式。请求签名、nonce、CSRF、时间戳、一次性上传流等不能盲目复用，提供重算/提取脚本及可解释错误。

### 6.6 多次重放、测试与脚本

- N 次运行、顺序/并发、间隔、速率上限、超时、取消、停止条件、明确重试策略；单次结果与汇总均可追踪。
- 参数集支持 CSV/JSON、变量作用域、边界值和显式组合方式；先显示总执行次数，避免隐式笛卡尔积。
- 前置脚本生成参数/签名/令牌，后置脚本提取变量并断言；支持请求间关联、“登录 → 提取 token → 查询 → 修改 → 验证”的工作流。
- 断言覆盖状态码、header、JSON 路径、schema、正文、Cookie/存储变化、耗时；二进制按字节/hash 比较，文本结构化 diff 可排除指定动态字段。
- 测试结果显示成功率、业务断言、p50/p95/p99、吞吐、实际并发、失败原因，区分排队时间和网络时间。小样本标明数量，不用不可靠百分位制造确定性。
- 脚本在独立运行器执行，具备执行时间、内存、日志与取消管理。文件/网络能力通过显式 SDK 提供；不能把 `node:vm` 当作运行不可信脚本的安全隔离。
- 测试配置记录种子、版本、变量和输入资产，保证配置可复现；不承诺外部服务器响应确定性。
- 后续加入 WebSocket/SSE 会话脚本、断网/延时/错误响应、请求阻断、离线缓存、页面与接口联合测试。压测作为本机能力的一部分，先验证实际负载，不声称替代分布式压测平台。

### 6.7 资源整理、接口统计与站点理解

- 资源按站点/页面/访问批次/类型/版本组织；同 URL 不同内容保留版本，同内容不同来源保留引用。支持图片网格、媒体预览、代码/文本/JSON、二进制查看和全局搜索。
- 大型搜索和解析后台运行，显示索引进度与范围；显示匹配片段不等于加载整个文件。
- 接口目录支持自动路径模板、手工合并/拆分、标签和备注；按环境、浏览器身份、时间与运行过滤，展示频率、失败、耗时、体积、缓存、请求/响应结构及版本差异。
- 关系链接页面动作、发起脚本、请求、响应资源、Cookie 和存储变化。因果证据、时间相关、推断关联分别标注；相近时间或相同参数不能直接证明因果。
- 站点档案汇总入口、页面、接口、资源、第三方依赖、存储用途、已知流程与历史变化。事实关联原始证据，自动总结可纠正。
- 契约、测试基线、资源版本支持固定和归档。镜像导出保留 manifest；下载完资源不等于站点可完整离线运行，离线回放另设可测目标。

### 6.8 Agent 友好的动作协议

Agent 能力从第一阶段建设，每个功能交付都同步提供结构化入口，不能到最后才套一层工具描述。

建议统一动作输入：目标引用、参数、预期对象版本、请求幂等键、完成条件与超时。长任务立即返回 `taskId`，支持状态、事件游标、取消与结果引用；大正文返回 artifact/content 引用与范围读取接口，不能默认把 GB 数据塞入工具上下文。

建议结果包含：`taskId / target / status / result / observedState / artifacts / warnings / error`。错误有稳定 code、可重试性、是否可能已产生效果，以及下一步可选动作。结构样例为未来契约，不是当前 API。

| Agent 需求 | 对应产品设计 |
| --- | --- |
| 先知道能做什么 | capabilities 按实际浏览器/配置报告，缺失给出原因 |
| 稳定找对象 | ID、语义定位和带版本快照；避免依赖当前 UI 焦点 |
| 高效阅读 | 摘要、筛选、游标、字段选择；需要时按范围读取原文 |
| 可组合动作 | 和人类操作共用动作服务，能创建模板/测试/工作流 |
| 等待结果 | task / wait / event；条件等待代替反复截图猜测 |
| 避免串台 | 明确目标、版本冲突处理、按目标排队、输入租约 |
| 失败后继续 | 检查点、结果未知状态、明确重试语义 |
| 人类检查 | 每个动作和报告有可打开的 UI 定位，时间线实时可见 |

保留外部 Agent 接入优先，内置模型助手可后续添加。内置助手与外部 Agent 共用协议；模型看到的网站内容作为数据，不能改变既定任务的目标和执行范围。人类可为一段工作流预先授权范围，无需每个微小操作都弹窗。

## 9. 验收体系与产品完成定义

### 9.1 一项功能必须有的证据

1. 真实用户流程能完成，包括失败、空数据与退出恢复。
2. UI 与 Agent 使用同一执行结果；涉及状态修改的动作有读回或业务断言。
3. 多工作区、多浏览器和并发编辑不会串目标或覆盖草稿。
4. 大数据量使用可接受，原始数据不会因显示上限被丢弃。
5. 配置、模板、脚本、任务和输出有版本和归属；打包版可运行。

任务状态采用“待设计 → 设计确认 → 开发中 → 验证中 → 已交付”；只有证据满足验收才标已交付。受限功能另列限制原因与补齐任务，不与完整实现混为一个勾选。

| 登录验证 | Cookie 存在但未登录、会话过期、二次验证、断网保留旧证据但标不可验证、账号/租户切换、SSO |
| 浏览器插件 | 版本与权限变化、启停/安装失败、需要重启、手工更改、插件与代理规则冲突、不可恢复配置 |
| 网络 | 直连、不同上游、认证错误、断网、代理故障、慢响应、部分传输 |
| 执行 | 原始捕获、两种重放、串行/并行、取消、超时结果未知、脚本异常 |
| 交互 | 小窗口、不同缩放、分栏、键盘、切换与恢复草稿、繁忙时继续操作 |
| 恢复 | 浏览器崩溃、采集进程崩溃、磁盘不足、数据库忙、终端重启、迁移失败 |

所有比较保留服务端 access/body 真值、浏览器实际状态及终端输出三份证据。完整性同时报告原始总数、已覆盖数、完整数、不完整数与原因；对浏览器内部流量等范围边界单列，不用排除项美化成“绝对 100%”。

工作区专门验收：在 A 登录受控站点账号 alice、启用插件 X 并保存资料；在 B 登录同站账号 bob、启用不同插件配置并保存另一组资料。两个同时运行且反复切 UI，核对服务端收到的账号、浏览器实际扩展状态和资料引用；随后休眠/恢复 A，确认 B 不变、A 历史仍在且登录重新验证。补测服务器让 alice 过期、插件 X 升级、代理失效、运行中崩溃、检查点恢复和共享资源删除。每一项同时比对 UI 摘要、Agent 返回与独立真值，不能只验证状态字段被成功写进数据库。

### 9.3 建议的性能验收目标

这些是待 M0 校准的目标，不是当前已达到的承诺。记录 CPU、内存、磁盘、Chrome/Node/应用版本、系统缩放、显示刷新率与 fixture。

- 10 万条请求常用列表滚动在参考机器达到 55fps 以上；采集时查询/切换保持可响应。
- 1GB 单正文与累计 10GB 采集不造成随总数据量线性增长的常驻内存；先设每采集工作进程的峰值增量预算为 256MB，通过实测细化，界面内存另报。
- 核心交互 p95 反馈目标 200ms 内；耗时操作立即进入任务态并持续展示进度。
- 采集性能按内容类型、大小、并发分别报告页面耗时、首字节、CPU、内存、磁盘及漏失；不继续用单一“低于 4%”代表所有负载。
- 取消后不再调度新步骤，2 秒内 UI 确认取消请求；在飞网络/远端副作用是否完成单独报告。
- 24h/72h 长稳检查内存趋势、队列、磁盘引用、实例退出和任务恢复；吞吐上限需测出饱和点，不能只证明轻负载通过。

## 10. 风险与关键设计决策

| 风险 / 决策 | 处理方式 | 决定时点 |
| --- | --- | --- |
| 全量采集路径可能改变页面时序或网络指纹 | M1 比较 CDP、代理及必要浏览器适配，记录真实影响；能力边界可见 | A03 / M1 |
| 代理看不到缓存或 SW 生成正文 | 多来源采集并关联；建立具体缺口任务，不假设代理覆盖全部 | M1 |
| 采集存储量长期增长 | 容量面板、归档、用户配置保留策略、固定重要资产；磁盘不足明确失败 | M1、M10 |
| 浏览器重放与独立 HTTP 不等价 | 两种模式显示执行器、身份、Cookie/代理/协议；对实际出站请求验收 | M5 |
| 多工作区规则、账号和任务串台 | 稳定 ID、按对象配置、运行快照、隔离测试 | M0、M2 |
| 状态组合爆炸与陈旧摘要 | 分层状态机；期望/实际/历史分离；事件与对账；freshness 逐项记录 | M0、M2 |
| 插件管理能力随浏览器变化 | 按目标版本验证适配器；不支持明确暴露；备份列出插件配置覆盖范围 | A11、M2 |
| 浏览器同步或服务端账号造成跨工作区影响 | 工作区不共享本地可变 profile；同步行为显式检测/配置；服务端同账号副作用单列 | M2、M4 |
| 恢复后误报登录有效或继续旧动作 | 登录证据置 stale；运行代次更新；未知结果任务不自动重发；恢复原始资料不重放操作日志 | M2、M8 |
| Cookie 恢复无法还原登录 | 恢复后验证实际访问；说明服务器会话/设备绑定等外部条件 | M4 |
| 人类与 Agent 并发修改 | 对象版本、输入锁、运行固定目标、可接管状态 | M0 起持续 |
| 脚本阻塞或越界访问 | 独立进程、资源限制、明确 SDK；不可信代码隔离单独验证 | M6 |
| 大规模资源分析堵住采集 | 后台索引、分块解析、任务优先级、查询范围与取消 | M7 |
| 站点图和 AI 总结误导 | 区分事实/推断、证据引用、置信度和手工纠正 | M7、M9 |
| 旧文档与新方向冲突 | 每个里程碑同步规格与状态，旧文档标历史；避免照旧约束缩减新目标 | M0 起持续 |

## 11. 后续开发任务的统一格式

每个任务按以下模板拆分，便于后续由开发者或 Agent 接续：

```text
任务编号 / 所属里程碑：
用户场景与期望结果：
现有实现及证据：
依赖与数据迁移：
对象、输入、输出、错误与完成条件：
工作区/身份归属、状态转换、期望与实际对账：
人类界面路径：
Agent 动作 / 查询 / 任务接口：
并发、失败、取消与恢复行为：
验收 fixture / 真值 / 打包验证：
交付证据位置：
已知限制及后续任务：
```

计划以**持久工作区状态模型与完整采集**为共同基础：工作区记住独立的登录、插件和历史，完整采集保存真实证据；在此之上建设浏览器控制、请求重放、测试编排与站点理解。人类可视化和 Agent 动作契约贯穿所有阶段。新功能若不能融入这条流程，应先解释它解决哪个用户任务，再进入排期。

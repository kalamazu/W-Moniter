# ADR-0002：正文证据链与显式保留清理

状态：已采用 · 2026-09-23
关联：T-005、T-008、T-009

## 决定

- 原始正文以 ContentStore 的 SHA-256 manifest 和去重块存储；SQLite 只保存请求引用。范围读取逐块校验，不为小窗口拼接整个正文。
- 采集结果与显式清理决定写入工作区内的 JSONL 哈希链，记录请求实例、序号、阶段、状态、大小、hash、原因和时间。清理先记录意图，再删除 manifest / 无引用块，更新 SQLite 引用，最后记录删除结果。
- 原始正文删除只接受带原因的显式动作 `content.revoke`；不因 UI 预览上限自动删除。工作区的物理存储与证据链彼此隔离。

## 边界与后续

- 哈希链能检测单条记录修改和链中断，但本机文件所有者可以替换整份账本；它不是法律意义的不可篡改存储。需要强不可抵赖性时，应接远端追加式/WORM 证据汇，且由独立密钥签名。
- 清理是显式策略动作，尚无自动 TTL/配额执行器；新增自动策略时必须先定义预览、导出和正在使用的引用保护。
- 跨主进程的 ContentStore 写锁尚无文件系统分布式互斥；当前每工作区只有一个应用主进程写入者。多进程共享同一工作区前必须升级锁机制。
- 旧的 SQLite BLOB 仍可读取与导出；新正文由存储子进程从 ContentStore 读取并校验，用于资源镜像、HAR/JSONL 等既有链路。

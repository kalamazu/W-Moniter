# ADR-0001：工作区先以独立目录与 SQLite 隔离

日期：2026-09-23 · 状态：已采纳（过渡方案）  
关联：[工程实施蓝图 §5 / migration 011](../智能Web管理终端-工程实施蓝图.md)

## 决策

在完整 `workspace_id/profile_id/partition` schema 迁移完成前，每个新工作区使用独立的 Chromium Profile、`monitor.db`、下载、规则和界面配置目录。升级前已有数据保持在默认工作区的旧目录，不移动、不复制。

## 原因

现有 SQLite 的 Cookie、站点镜像和部分查询使用全局主键。直接让多个身份写同一数据库会造成归属混淆；先拆分数据目录可交付真实并发浏览器能力，同时避免把未验证的 schema 改造和控制器重构绑成一次高风险提交。

## 后果与退出条件

- 好处：A/B 工作区可并发运行，浏览器资料和当前采集历史不会互相写入。
- 限制：无法做跨工作区统一查询、共享内容去重或数据库级 scope 审计；这不是最终数据模型。
- 退出：M1 ContentStore 与 migration 009–011 完成后，将各工作区数据迁入带明确 scope 的库表；迁移要保留旧来源、校验行数/正文引用，并提供可暂停回滚点。

# ADR-0003：采集来源按证据选择，不静默切换

状态：已采用（技术路线约束） · 2026-09-23
关联：[T-010](../tasks/T-010-capture-coverage-probe.md)、[能力账本](../architecture/capture-coverage.md)

## 证据与选项

受控 origin 证明：现有 Fetch 路径可取回 2 MiB 响应及会结束的未知长度流；独立 CDP `Network.getResponseBody` 在相同样本可返回正确字节。Fetch 对 SSE、下载、上传原文及 WS 帧不是同一种正文来源；代理模式的大上传和 WS 在当前版本还有实际转发/握手缺口。

候选路径：继续单用 Fetch、按内容种类接 CDP/下载/WS 来源、代理 tee 网络流、浏览器定制。单用 Fetch 无法满足全量；直接把代理设为默认来源也不安全，因为上述转发失败会影响页面行为。

## 决定

保持现有受控浏览器的来源不变，先实现来源能力矩阵和显式 gap。T-012 为可持续接收字节的内容通道；上传/代理 tee、下载、WS/SSE 分别由后续来源适配任务接入。每次切换来源须以同一 origin 真值、页面消费、hash、延时和内存对比证明安全，且不能重复登记同一交换。

本 ADR 不降低“全量采集”目标。代理上传停滞和 WS 失败是待修复缺陷；标准路径若最终不能覆盖某类内容，再比较辅助扩展或定制 Chromium 的维护/打包成本。

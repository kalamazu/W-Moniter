### 7.4 分析层：从「记录」到「能下判断」

采集层负责「一条不落地记下来」，分析层负责「算成能直接下判断的形状」。它**不加采集源**，
只读已经落库的 `requests` / `bodies` / `events` / `ws_frames`，所以能在不起浏览器的情况下自检
（`npm run test:analytics`，40 项全是「算出来的东西对不对」）。

**接口画像**按「方法 + 主机 + 路径模板」聚类。路径模板只做**保守替换**：`{int}` / `{uuid}` /
`{hex}` / `{date}` / `{token}` / `.{hash}.`。宁可多出两个模板，也不要把 `/users/me` 和 `/users/1`
并成一个 —— 合错了会把两个接口的字段分布与契约搅在一起，而「多一个模板」最坏只是多看一行。

**`optional` 是「不是每个样本都有」**，而且**父层的可选要往子层传**：整个 `bonus` 只在一半样本里
出现时，`bonus.deep` 也必须是可选的（`optional || seen < count`）。这条一开始漏了，契约回归就看不见
「新字段只在部分请求里出现」——偏偏那是最常见的回归形态。

**调用图**只画「谁触发了谁」中能站住的那部分：发起链（`initiator_stack`）里能解出脚本/文档的边，
以及 document → 子资源的边。功能簇是图的**连通分量**（互相牵动的一组东西），不是聚类算法 ——
它回答的是「动一个会不会牵连另一个」，用连通分量就够了，不需要更花哨的东西。

**关联分析**四类：共享响应体（同一 `body_hash` 被多个 URL 取到）、重定向链（同 `requestId` 多跳）、
跨域加载关系（`frame_host` → 请求 `host`，**同域不算**，否则「关联」就等于「所有请求」）、
跨端点复用的 query 取值（同一个 `trace_id` / `session` 出现在多个端点）。后者带一个噪音名单
（`_t` / `ts` / `nonce` / `callback` …），不带的话「共享参数」会被缓存击穿参数淹掉。

**契约回归**：`POST /contracts` 把「端点 / 状态码 / query 与请求体字段 / 响应 JSON 形状」拍成一份
JSON 存进库，之后 `GET /contracts/:id/diff` 拿它和「当前」比。标准动作是
**跑一遍 → 拍基线 → 改东西 → 再跑一遍 → diff**。

**导出**统一落在 `<dbPath 所在目录>/exports/`：HAR 1.2（剔除 CDP 伪头，否则 DevTools 打不开）、
JSONL（一行一条）、资源镜像（按类型分子目录，文件名 = `hash 前 8 位 + 原名`，同一份正文只写一次）。
镜像的「同一份正文只落一个文件」不只是省磁盘 —— 「共享响应体」那条关联就是靠它成立的。

**下载落到 `<数据目录>/downloads/`**（`MONITOR_DOWNLOAD_DIR` 可覆盖，空串 = 交回浏览器默认）：
自动化跑一遍不该往用户的下载夹里丢东西，而「文件真的落了盘」是事后取证要的外部证据。
`Browser.setDownloadBehavior(eventsEnabled: true)` 让 `begin / inProgress / completed` 都上得来。
